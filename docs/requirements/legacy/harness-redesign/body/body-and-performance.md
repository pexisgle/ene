# body とパフォーマンスプロトコル

> 実現する要件: **P-401..P-407**(身体と表示)、P-303(感情→表情写像の消費側)。

## 1. soul/body 分離(P-401)

- **soul** は人格・感情・記憶・声([../companion/soul-and-affect.md](../companion/soul-and-affect.md))。
- **body** はアバター資産・表情/モーションカタログ・感情写像表。
- 両者は独立した永続エンティティで、soul の `body_ref` で結合する。
  結合は実行時に検証され、写像表の不一致は警告+最近傍フォールバック。
- 既定は「セット=1キャラ」([../character/package-format.md](../character/package-format.md))だが、
  自由な組み替えは公式機能(P-402)。

## 2. パフォーマンスプロトコル

soul 側(感情エンジン・内面・発話)が生成し、body 側が消費する
**キューの言語**。アバター形式(VRM/Live2D/テキスト)に依存しない。

### キュー種別

| キュー | フィールド | 説明 |
|---|---|---|
| `expression` | `label, intensity: 0..1, duration_ms?` | 表情。ラベルは感情ボキャブラリと同じ集合 |
| `motion` | `name, layer: base\|overlay\|one_shot, intensity?` | モーション。カタログ参照 |
| `lookat` | `target: user\|away\|screen, weight: 0..1` | 視線 |
| `lipsync` | `amplitude, viseme?` | リップシンク(音声再生に同期) |
| `posture` | `pose: relax\|alert\|thinking, blend: 0..1` | 姿勢の粗制御 |

- キューは**検証**されてから body へ渡る: 存在しない表情/モーションは
  棄却+ライフサイクル警告(soul と body の不整合の検知)。
- 裁定器(ヒステリシス・レート制限)は soul 側が所有
  ([../companion/soul-and-affect.md §6](../companion/soul-and-affect.md#6-出力裁定p-304))。
  body 側は届いたキューを**描画へ変換するだけ**。

### 感情→表情写像(P-303)

- 写像表は **body パッケージが所有**する:
  `{ emotion_label → expression_label(+ 補正 intensity) }`。
  同じ「happy」でも body によって笑顔の作りが違うため。
- soul 結合時に写像表の網羅性を検証。欠けは最近傍ラベルで
  フォールバック(検証結果は UI に表示、P-402)。

## 3. 発話との同期(リップシンク)

- TTS の音声ストリームは body に直接渡り、再生位置と同期して
  `lipsync` キューを生成する(クライアント描画側で計算)。
- 発話テキストの確定と音声再生は独立で、テキスト先出し・
  音声後追いが許される(テキスト専用表示との整合)。
- 割り込み時はリップシンクを即停止
  ([voice.md §4](voice.md#4-割り込み状態機械p-103))。

## 4. 自律アニメーション(P-106)

- ターンを起こさない最小限の生命感: 瞬き・呼吸・視線の揺らぎ。
- 感情状態を**弱く**反映する(高覚醒=動きが多い、疲労=少ない)。
- 実装はクライアント側のプロシージャル生成。コアデーモンは
  感情の粗状態(5段階)だけを配信する。

## 5. 複数 body の同時表示(P-405, stretch)

- stage は複数の (soul, body) 対を並べて描画できる。
- body ごとに独立のキュー購読。音声出力の調停は
  [voice.md §6](voice.md#6-複数体の調停p-405-対応)。
- 同時表示の上限はクライアントの描画性能に委ねる(既定の推奨 2)。

## 6. hot swap とテキスト専用モード(P-406, P-407)

- **hot swap**: セッション中の body 差し替えは、キュー購読の
  切り替えのみで実現。会話・ターンは影響を受けない。
  差し替えはセッションログに `body/swapped` ライブイベントで通知
  (永続は soul の状態変更として companions.db へ)。
- **テキスト専用モード**: `body_ref = none`。パフォーマンスキューは
  生成を続けるが購読者なし(感情の一貫性は保たれる)。
  軽量構成・headless の既定。

## 7. body 形式の拡張性(P-408, 後継)

v1.0 は VRM 1.0 のみ実装するが、形式の接点は固定する。

| 形式 | v1.0 | 接点 |
|---|---|---|
| VRM 1.0 | 実装 | wgpu ネイティブ描画(desktop)、既存 ene-vrm を基に再構築 |
| Live2D | 後継 | キュー→パラメータ写像の adapter |
| 静止画(テクスト) | 後継 | expression→画像差分の切替 |
| テキストアバター | 後継 | キューのテキスト化表示 |

## 8. 障害モード

| 障害 | 挙動 |
|---|---|
| 描画初期化失敗(GPU 不可) | テキスト専用モードへ自動退化+通知。会話は継続 |
| キューの検証失敗(未知ラベル) | 棄却+警告。連続失敗は写像表の再検証を提案 |
| hot swap 中のキュー | 旧 body 宛のキューは破棄、新 body は次のキューから |
| リップシンクと音声のずれ | 再生位置を正として再同期(100ms 以上のずれで) |

## 9. 設定キーと既定値

| キー | 既定 | 説明 |
|---|---|---|
| `body.render.enabled` | `true` | 描画の有効性(false = テキスト専用) |
| `body.render.max_concurrent` | `2` | 同時描画の推奨上限 |
| `body.autonomy.enabled` | `true` | 自律アニメーション |
| `body.fallback.nearest_expression` | `true` | 写像欠けの最近傍フォールバック |
