# ene 要件定義

ステータス: **基本要件策定済み**

このフォルダには、ene がどのような製品であり、ユーザーから見てどう動作すべきかを定めた「正式な要件（マスタードキュメント）」をまとめています。過去の実装やテスト、Git の履歴は経緯を知るための参考資料であり、過去のコードが存在することだけを理由に仕様として採用することはありません。

なお、要件定義は内容が安定するまで日本語のみで管理します（英語版は作成しません）。

## ドキュメント構成

- **[製品定義 (product.md)](product.md)**: 製品のコンセプト、登場する重要概念、対象ユーザー、およびあえて対象外とする事項（非目標）をまとめています。
- **[要件 (requirements.md)](requirements.md)**: ユーザーから見えるシステムの振る舞い、安全性やプライバシーのルール、データ管理の仕様などを定めた中心ドキュメントです。
- **[受け入れ条件 (acceptance.md)](acceptance.md)**: 開発マイルストーンごとに「何をもって完了とするか」を確かめる代表的な検証シナリオです。
- **[参考資料 (references.md)](references.md)**: 設計の参考にした他社製品やオープンソース標準、ene との相違点を記録した資料です。

用語の意味は「製品定義」、具体的な振る舞いは「要件」を参照してください。「受け入れ条件」や「参考資料」が勝手に新しい製品仕様を作ることはありません。

## 要件（ここ）と設計（design）の役割分担

### このドキュメント（要件）に書くこと
- 製品としての提供価値と対象範囲
- ユーザーから見える機能、操作、状態変化、エラー時の振る舞い
- プライバシー、セキュリティ、権限（Permission）、データ保持に関するルール
- 採用する外部標準や形式（MCP、Agent Skills、VRM 1.0 など）やセキュリティ隔離の方針
- 実装方法が変わっても保つべき品質や使い勝手

### 内部設計（design）に任せること（ここには書かないこと）
- 内部の具体的な仕組み（データベースのテーブル定義、内部の型定義、検索アルゴリズムなど）
- クレートやプロセスの分割方法、内部通信のメッセージ形式、プロンプトの組み立て順
- 特定のライブラリ選定、OS 固有の API、暗号アルゴリズム、キャッシュの持ち方などの実装詳細
- モデル名、価格、OS バージョン、スペック数値の一覧（検証環境として変動するもの）
- 画面の色やポップアップのレイアウトなどの UI 実装詳細

> [!NOTE]
> 要件本文の「〜する」「〜できる」「〜しない」という記述は、システムが満たすべき正式な仕様として扱います。
