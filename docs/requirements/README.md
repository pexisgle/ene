# Ene 要件定義

状態: **再構成済みBaseline**
最終確認: 2026-09-05

このディレクトリは、Eneがどういう製品であり、外部からどのように振る舞うべきかを定義する唯一の要件正本である。既存実装、テスト、過去の文書、Git履歴は現状や経緯を知る資料であり、それだけを理由に要件へ昇格させない。

要件は、安定するまで日本語だけで管理する。並行した英語版は作らない。

## 文書

- [製品定義](product.md): 製品の目的、主要概念、対象、非目標を定義する。
- [要件](requirements.md): ユーザーから観測できる挙動、安全境界、データ契約を定義する唯一の行動要件正本。
- [受け入れ条件](acceptance.md): 現在の実装milestoneと、その合否を確認する代表シナリオ。全体要件を縮小または追加しない。
- [参考資料](references.md): 参考にした製品・標準、採用した考え方、Eneでの差分を記録する非規範資料。

同じ必須挙動を複数文書へ転載しない。用語の意味は製品定義、必須挙動は要件を参照する。受け入れ条件と参考資料が新しい製品要件を作ることはない。

## 要件と設計の境界

要件へ置くもの:

- 製品の価値と範囲
- ユーザーから確認できる能力、制御、状態、失敗時の挙動
- Privacy、Security、Permission、データ保持に関する契約
- 実装方法を変えても維持すべき品質

要件へ置かないもの:

- DB schema、内部型、分類、数式、検索・更新アルゴリズム
- process、crate、IPC、wire format、Prompt本文やcontextの組み立て順
- sandbox、暗号、cache、描画、OS統合の具体技術
- model、価格、OS version、hardware、数値thresholdの固定一覧
- 色、widget、popup等の画面実装詳細
- 既存実装との互換性だけを目的とする制約

`する`、`できる`、`しない` と記載した要件本文を製品契約として扱う。個別のFR/NFR等のIDは付けず、意味のある見出しを参照する。具体的なProvider catalog、Support Matrix、性能budgetは、実測と公開範囲に応じて受け入れ条件側で更新する。
