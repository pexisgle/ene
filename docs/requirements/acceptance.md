# 現在の受け入れ条件

ステータス: **最初の開発マイルストーン (Milestone 1)**

このドキュメントでは、[製品要件 (requirements.md)](requirements.md) のうち、**最初に開発して動作確認（検証）を行う具体的な範囲とテストシナリオ** を定めます。

本書に記載のない要件を諦めるわけではなく、また製品全体に新しい仕様を追加するものでもありません。マイルストーン完了時に、実際の測定結果や次期計画に合わせて内容を更新します。

## 動作確認環境 (Support Matrix)

| 項目 | 検証環境 |
|---|---|
| Windows | Windows 11 (x86-64) |
| Linux | NixOS 26.11 (x86-64, KDE Wayland) |
| UI言語 | 日本語、英語 |

| 同梱キャラクター | 公式キャラクター `ene` |

> [!NOTE]

## 今回のマイルストーンの範囲

### 今回実装・検証する機能
- 初回セットアップから最初のテキスト会話までの流れ
- 基本的なデスクトップアバター（3Dモデル）の表示
- パートナーとの一対一のテキスト会話タイムライン
- パートナーごとの記憶機能（経験の要約、記憶の形成、由来の確認、会話による訂正、プライバシー目的の完全削除）
- 1つの作業フォルダ（Workspace）を対象とし、作業用エージェントへ委任するファイル操作タスク
- パートナーを通じたタスクの進捗確認、追加指示、キャンセル、結果報告
- クライアント画面を閉じてもホスト側でタスクが継続すること、およびホスト再起動後に手動で再開できること
- OpenAI の利用量や発生費用の確認、および API キー等の秘密情報の漏えい防止
- 各種エラー発生時のデータ保護と、テキスト管理画面による復旧操作
- Windows / Linux 両OSでの基本性能テスト

### 次回以降のマイルストーンへ回す機能
- ホストPCの自動起動、およびバックアップからの全体復元
- 音声会話、画面観測（Observation）、グループ会話、パートナー同士の自発的な交流
- パートナー間で共有されるグローバル記憶
- 経験からの新しいスキルの自動生成・改善
- パートナーの感情や性格の長期的な変化
- ユーザーや他のパートナーとの関係性の長期的な発達
- スケジュール実行、リモート端末からの接続、キャラクターの編集やパッケージ配布
- OpenAI 以外のプロバイダー対応や自動フォールバック

## 代表的な検証シナリオ (End-to-End)

### 1. セットアップと最初の会話
1. 新規環境で ene を起動する。
2. UI言語（日本語/英語）、同梱キャラクター `ene`、クラウド送信データと費用の説明、OpenAI の API キー、使用モデルを案内通りに選択する。
3. API キーを登録しただけでは通信は始まらず、メイン LLM への割り当てを確認して初めてセットアップが完了することを確認する。
4. `ene` から作られたパートナーにメッセージを送り、同一タイムライン上で自然な返答が得られることを確認する。
5. 設定画面でUI言語を切り替えても、パートナーとの会話履歴がそのまま保持されていることを確認する。

### 2. 基本的なアバター表示 (Desktop Body)
1. 対応OS上で、背景が透過したオーバーレイとしてアバターが表示されることを確認する。
2. アバターをドラッグして移動したり、サイズ変更・一時非表示にしたりしても、通常のデスクトップ操作を邪魔しないことを確認する。
3. 待機中（アイドル）と応答中（発言中）で、表情や仕草が適切に変化することを確認する。
4. 万が一アバター表示がクラッシュしたり停止したりしても、チャット画面や設定画面は問題なく操作できることを確認する。

### 3. 会話を通じた記憶の形成と管理 (Memory)
1. パートナーとの普段の会話の中で、今後の役に立つ出来事や自分の好みを伝える。
2. メッセージを丸ごとコピーして保存するのではなく、出来事の要点をまとめた「経験の要約 (Experience Summary)」を根拠として、パートナー専用の記憶が正しく作られることを確認する。
3. 管理画面から、作られた記憶の内容、適用範囲、重要度、根拠となった要約、作成日時が確認できることを確認する。
4. アプリやPCを再起動した後の会話でも、過去に覚えた内容をパートナーが自然に思い出せることを確認する。
5. 「実はあれは間違いだったんだ」と会話で訂正した場合に認識が正しく更新されること、また「前はこうだったが今は変わった」という状況の変化も過去の履歴を壊さずに最新状態へ更新できることを確認する。
6. 更新された記憶の管理画面から、現在の内容だけでなく、過去の変更履歴や根拠となった会話要約を確認できることを確認する。
7. 「これ覚えておいて！」と頼んだ内容は優先的に記憶される一方、API キーなどの機密情報は依頼があっても絶対に記憶として保存されないことを確認する。
8. 単なる雑談など、長期的に覚えておく価値がない情報はむやみに記憶として溜め込まないことを確認する。
9. 同じ話を何度もした場合、同じ記憶が重複して増えるのではなく、既存の記憶が補強・統合されることを確認する。
10. 「今の話は忘れて」「気にしないで」といった日常的な依頼では、記憶の想起優先度が下がる（自然な忘却）だけで、データ自体が物理削除されるわけではないことを確認する。
11. **指定データの完全削除 (targeted deletion)**: セキュリティやプライバシー目的で特定のキーワードの完全消去を指示した場合、会話履歴、要約、記憶、変更履歴、検索用データから対象情報が機械的に完全に消去され、一切残存しないことを確認する。
12. 完全消去の処理中に別の記憶形成が動いても、消去対象の情報が後から復活して保存されることがないよう厳密に保護されていることを確認する。

### 4. ワークスペースでのファイル作業タスク
1. 既存ファイルが入ったフォルダを作業場（Workspace）として指定し、ファイルを読んで新しい Markdown レポートを作成するようパートナーに依頼する。
2. まとまったファイル作業が「タスク」として登録され、裏で動く作業用エージェント（Task Agent）に委任されることを確認する。エージェントには対象フォルダ内のファイル一覧・読込・作成・編集のみが許可される。
3. エージェントが作業している間も、パートナーとは普段通りにチャットができ、進捗の確認や作業方針の変更を伝えられることを確認する。
4. 作業を途中でキャンセルした場合、その時点までに完了した変更内容と残ったファイルがきちんと報告されることを確認する。
5. 作業が正常に完了した際、変更したファイル名や保存場所、やり残した事項がパートナーから分かりやすく報告されることを確認する。
6. 作業フォルダ外への不正なアクセス（パス・トラバーサル）、シェルコマンドの勝手な実行、外部ネットワーク接続などが厳格に遮断されることを確認する。
7. タスクが完了または終了しても、作業フォルダ内のファイルが勝手に消去されないことを確認する。

### 5. クライアントとホストの動作継続
1. 時間のかかるファイル作業タスクを開始した状態で、操作画面（クライアント）のウィンドウを閉じる。
2. バックグラウンドのホストPC上で作業がそのまま継続し、再度クライアントを開いたときに進捗や結果を正しく確認できることを確認する。
3. 作業中にホストPC側が終了・再起動した場合、危険を避けるためタスクは勝手に自動再開せず、保存されていた進捗を示した上でユーザーの再開指示を待つことを確認する。

### 6. エラー発生時の安全性とデータ保護
以下の異常・エラーが発生しても、保存済みの会話履歴や記憶、タスクの記録が破損せず、テキスト管理画面から安全に状態確認や復旧ができることを検証する：
- API キーなどの認証情報の誤り
- AI プロバイダーの障害やネットワーク切断
- アバター描画プロセスのクラッシュ
- 作業用エージェントの作業中のクラッシュ
- タスクの途中キャンセル
- ファイル保存中の突然のプロセス終了

> [!IMPORTANT]
> 外部への変更が成功したか不明な状態で失敗した場合は、二重実行の事故を防ぐため自動での再実行は行わず、ユーザーに状況を伝えて指示を仰ぎます。

### 7. 利用量・費用の透明性と機密保護
1. 会話やタスク実行後に、消費したトークン数（入力・出力・キャッシュ）と発生した費用の内訳を管理画面で明確に確認できること。
2. 登録した API キーなどの秘密情報が、AI に送るプロンプト、会話履歴、記憶データ、タスク結果、ログ画面、エラーメッセージなどに一切漏洩・露出しないことを自動検査と目視で確認する。

## 性能基準 (Performance Gates)

Windows および Linux の双方において、以下の基準を満たすことを確認します：

- **アイドル時の軽量性**: セットアップ完了後、推論を行っていない待機状態（5分間）において、ene プロセス全体の平均 CPU 使用率が 10% を超えないこと。
- **メモリ消費量**: 同期待機状態において、ホストとクライアントを合わせた常駐メモリが 2 GiB を超えないこと。
- **アバター描画の軽快さ**: 通常のアバター表示中、平均 30 FPS 以上を維持し、PC の他の操作を 1 秒以上ブロックしないこと。
- **操作の即応性**: 一時停止、キャンセル、ミュートなどの操作は、入力から 1 秒以内に受付状態が画面に反映されること。
