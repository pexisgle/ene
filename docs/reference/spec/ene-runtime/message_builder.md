# `MessageBuildContext` & Prompt Formatting Specifications

The `message_builder` module is responsible for compiling LLM conversation contexts, system instructions, and overlay mascot behavior constraints. Crucially, it manages the formatting of expression cue markers like `<|perf:expr=NAME|>` to control mascot visual overlays.

---

## 1. Input Parameter Struct

### `MessageBuildContext<'a>` (Public / Struct)
Holds all parameters required to build the conversation's message history:
*   `card: &'a CharacterCardV3`: The active character definition.
*   `user_input: &'a str`: Current raw user prompt.
*   `history: &'a [ene_mind::HistoryEntry]`: Current active conversation history.
*   `runtime_context: Option<&'a str>`: Context blocks (e.g. tool execution summaries) appended before the user input.
*   `runtime_rules: &'a str`: Override behavior guidelines prepended at boot time.
*   `user_name: &'a str`: Display name of the user.
*   `prompts: &'a PromptLibrary`: Localized prompt template library.
*   `emotion_enabled: bool`: Flag indicating whether the emotional runtime is active.

## 2. System Prompt Composition

#### `build_system_prompt`
*   **Signature**:
    ```rust
    pub fn build_system_prompt(
        card: &CharacterCardV3,
        runtime_rules: &str,
        user_name: &str,
        prompts: &PromptLibrary,
    ) -> String
    ```
*   **Assembly Order**:
    Combines text blocks in the following priority:
    1.  **Mascot Context Frame**:
        Renders overlay constraints using `prompts.system().render_mascot_context(char_name, user_name)`. Instructs the model that it lives on screen, must respond concisely, and must avoid heavy paragraphs.
    2.  **Runtime Rules**:
        Appends behavior rules (falling back to `DEFAULT_RUNTIME_RULES` if empty).
    3.  **Character Identity**:
        Appends the character card's `system_prompt`, `personality`, and `description`.
    4.  **Scene Scenario**:
        Appends the card's active `scenario`.
*   **CBS Macro Expansion**:
    Runs `expand_cbs_macros` on the compiled prompt, substituting instances of `{{char}}` and `{{user}}` with the character name and user name respectively.

## 3. Output Control Contracts (PHI)

Ene supports two modes for visual expressions: inline marker insertion (LLM-driven) and engine-side appraisal (deterministic).

#### `build_expression_phi`
*   **Signature**: `pub fn build_expression_phi(card: &CharacterCardV3, prompts: &PromptLibrary) -> Option<String>`
*   **Description**: Used in inline marker mode (when the emotion engine is disabled). Instructs the LLM to output a performance marker tag (e.g., `<|perf:expr=joy|>`) at the beginning of its message.
*   **Mechanics**: Resolves valid expressions defined in the character card using `resolve_expressions(card)` and outputs them as a whitelist in the prompt.

#### `build_natural_dialogue_contract`
*   **Signature**: `pub fn build_natural_dialogue_contract(card: &CharacterCardV3, prompts: &PromptLibrary, user_name: &str) -> Option<String>`
*   **Description**: Used in engine-controlled mode (when the emotion engine is enabled). Explicitly instructs the LLM **not** to output expression markers, since emotions are computed downstream by the Output Arbiter.

#### `build_cognitive_output_contract`
*   **Signature**:
    ```rust
    pub fn build_cognitive_output_contract(
        card: &CharacterCardV3,
        prompts: &PromptLibrary,
        emotion_enabled: bool,
        user_name: &str,
    ) -> Option<String>
    ```
*   **Description**: Dispatches to `build_natural_dialogue_contract` if `emotion_enabled` is true, otherwise falls back to `build_expression_phi`.

## 4. Message List Assembly & Helpers

#### `build_messages`
*   **Signature**: `pub fn build_messages(ctx: &MessageBuildContext<'_>) -> Result<Vec<LlmMessage>, EneRuntimeError>`
*   **Assembly Order**:
    1.  `System`: The base system prompt generated by `build_system_prompt`.
    2.  `System`: Initial turn example messages (`mes_example`) from the character card.
    3.  `History` (`HistoryEntry`): Appends conversation history entries with alternating `User` and `Assistant` roles.
    4.  `System`: Output control contract (PHI) compiled by `build_cognitive_output_contract`. Placing this after history reinforces output compliance.
    5.  `User`: Appends the current user prompt, injecting `[Runtime Context]` blocks if `runtime_context` is present.

#### `sys_msg`
*   **Signature**: `fn sys_msg(content: impl Into<String>) -> LlmMessage`
*   **Description**: Helper function to construct a `System` role message for the LLM payload.

#### `user_msg`
*   **Signature**: `fn user_msg(content: impl Into<String>) -> LlmMessage`
*   **Description**: Helper function to construct a `User` role message for the LLM payload.

#### `asst_msg`
*   **Signature**: `fn asst_msg(content: impl Into<String>) -> LlmMessage`
*   **Description**: Helper function to construct an `Assistant` role message for the LLM payload.
