# `CognitionEngine` & Turn Lifecycle Specifications

The `CognitionEngine` is the primary orchestrator facade for the `ene-mind` cognitive pipeline. It coordinates pre-turn analyses, hybrid memory recall, prompt layout formatting, expression rendering resolution, and background memory consolidation.

---

## 1. Struct Definition

### `CognitionEngine` (Public / Struct)
Aggregates all modular sub-components representing the brains of the AI companion:
```rust
pub struct CognitionEngine {
    pub pre_turn: PreTurnAnalyzer,
    pub context: ContextManager,
    pub memory_writer: MemoryWriter,
    pub recall: RecallPlanner,
    pub emotion: EmotionEngine,
    pub character: CharacterProcessor,
    pub prompt_packet: PromptPacket,
    pub output: OutputArbiter,
    pub commitments: CommitmentLedger,
}
```
*   `new() -> Self`: Initializes each sub-component with default values.

## 2. Configuration & Memory Synchronization

### `validate_config`
*   **Signature**: `pub fn validate_config(config: &MindConfig) -> Result<(), CognitionError>`
*   **Description**: Validates that the token budget allocations (e.g. system instructions, memory recall, history limit) fit safely within the model's absolute limits.

### `sync_character_memories`
*   **Signature**:
    ```rust
    pub async fn sync_character_memories(
        &self,
        ctx: TurnContext<'_>,
        previous_hash: Option<u64>,
    ) -> Result<(CharacterMemorySyncReport, u64), CognitionError>
    ```
*   **Description**: Writes and indexes the character card's lorebook entries and style examples into the persistent database. Skips indexing if the card hash matches the previous cache.
*   **Connections**: `CharacterProcessor::sync_card_memories`, `MemoryStore`, `EmbeddingProvider`.

## 3. Pre-Turn Pipeling (before_turn / before_proactive_turn)

### `before_turn`
*   **Signature**: `pub async fn before_turn(&self, ctx: TurnContext<'_>) -> Result<PreTurnOutput, CognitionError>`
*   **Process**:
    1.  **Emotion Update**:
        -   Retrieves the current `AffectState` (PAD values) from the database.
        -   Applies pending emotion classifier proposals (`PendingAffectProposal`) generated by the previous turn's background tasks.
        -   Calculates temporal decay based on elapsed time and runs appraisal rules on the user's input text via `EmotionEngine::update_turn`.
    2.  **Memory Recall**:
        -   Computes query embeddings. Runs `execute_hybrid_recall` to fetch episodic and semantic memories matching the query vector and current emotional valence.
    3.  **Commitment Retrieval**:
        -   Queries up to 16 active commitments (promises/tasks) from `CommitmentLedger::list_active` and translates them into system prompt cues.
    4.  **Output**: Returns the aggregated `PreTurnOutput`.

### `before_proactive_turn`
*   **Signature**: `pub async fn before_proactive_turn(&self, ctx: TurnContext<'_>) -> Result<PreTurnOutput, CognitionError>`
*   **Description**: A lightweight pre-turn function for proactive turns. Because there is no user input query, it bypasses embedding computation and vector recall, loading only emotion states and commitments.

## 4. Prompt Composition (compose_prompt_packet)

### `compose_prompt_packet`
*   **Signature**:
    ```rust
    pub async fn compose_prompt_packet(
        &self,
        ctx: TurnContext<'_>,
        pre: &PreTurnOutput,
        prefetch: ComposePrefetch,
    ) -> Result<ComposedPrompt, CognitionError>
    ```
*   **Process**:
    1.  Compiles the character's Identity Kernel using `CharacterProcessor::compile_kernel`.
    2.  Selects relevant conversational style examples matching the input.
    3.  Formats the active emotional state (mood label + valence/arousal values).
    4.  Fetches active scene context summaries using `load_active_scene_summary`.
    5.  Slices conversation history to fit within `recent_turns` limits.
    6.  Aggregates parameters into `PackInput` and runs `pack_prompt`. The budget limits from `ContextBudget` are applied; lower-priority sections are dropped if budgets are exceeded.
    7.  Returns the compiled LLM messages as `ComposedPrompt`.

## 5. Post-Turn Pipelines (finalize_turn_post / write_memories_deferred)

### `finalize_turn_post` (Synchronous Finalize)
*   **Signature**: `pub async fn finalize_turn_post(&self, store: &MemoryStore, config: &MindConfig, input: &PostTurnInput<'_>) -> Result<(), CognitionError>`
*   **Description**: Executed immediately after LLM streaming completes. It writes the updated `AffectState` back to the database synchronously, keeping turn latency low.

### `write_memories_deferred` (Deferred Consolidation)
*   **Signature**:
    ```rust
    pub async fn write_memories_deferred(
        &self,
        store: &MemoryStore,
        config: &MindConfig,
        input: &OwnedPostTurnInput,
        providers: MemoryWriteProviders<'_>,
    ) -> Result<(), CognitionError>
    ```
*   **Description**: Runs asynchronously in the background.
    1.  `MemoryWriter::write_memories`: Spawns the `MemoryArbiter` to extract key facts and episodic highlights via LLM extraction prompts and saves them in the vector store.
    2.  `MemoryWriter::apply_forgetting`: Applies decay rules to existing memories and triggers status transitions (e.g. archiving faded facts).

## 6. Expression Resolution (resolve_expression_turn)

### `resolve_expression_turn`
*   **Signature**:
    ```rust
    pub fn resolve_expression_turn(
        &self,
        config: &MindConfig,
        card: &CharacterCardV3,
        affect: &ene_store::AffectState,
        response_text: &str,
        llm_proposal: Option<&str>,
        previous_expression: &str,
        elapsed_since_change: Option<Duration>,
    ) -> (ExpressionDecision, ene_store::AffectState)
    ```
*   **Description**: Determines the final 3D visual expression for the mascot.
*   **Mechanics**: Resolves the expression using `OutputArbiter::resolve` by examining PAD values, checking punctuation patterns in the assistant text (e.g. exclamation marks), and checking the elapsed time since the last transition to prevent chattering. Returns the decision and an updated `AffectState`.
