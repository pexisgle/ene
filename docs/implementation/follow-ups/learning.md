# Learning と Memory 形成の後続計画

[実装ガイド](../README.md) / [Stage 3](../stages/stage-3.md) / [Stage 7](../stages/stage-7.md)

Stage 3 の完了記録は維持する。この計画は、現行 Desktop から学習用推論を設定できない問題と、記憶形成経路の改善を扱う。着手時の source と実機状態を確認する。現行要件にない Jev への送信と方式選択は、要件・設計で製品契約を定めてから実装する。

## L1: 学習用モデルの設定と可視化（先行）

- 初回設定または管理画面から Learning 用 provider・model・credential・同意を明示的に登録できるようにする。Dialogue の割り当てを Learning に複製しない。Host の Learning admission と GUI の設定状態を同じ正本へ接続する。
- Learning 未設定、認証失効、利用不可、同意不足、上限到達、形成候補なしを区別して記憶画面または管理画面へ示す。空一覧を形成処理の成功と誤認させない。設定への導線を設け、Companion 停止や provider 不通でも管理可能にする。
- 後から Learning を有効にした際の過去会話の扱いを要件・設計で決める。外部 API と費用を伴う自動バックフィルを既定で始めない。過去の生会話が残っていない場合の扱いも明示する。
- 新規データ領域から Dialogue と Learning を別々に設定し、保存価値のある会話の終了後に Memory と根拠 Summary を確認する。保存価値のない会話に形成を強制しない。Learning 未設定・失効・再起動後の状態と理由、同意なしの provider 送信ゼロを検証する。

## L2: 形成プロンプトと候補判断（L1 後）

- 固定指示と JSON 出力契約を、`ene-learning` に同梱する版付き UTF-8 テンプレートへ分離する。可変の既存記憶・会話・件数上限は明示的な差し込み位置で組み立て、会話本文をテンプレートとして解釈しない。配布物のみで動作させ、差し込み位置・出力契約をテストする。診断に会話や完成プロンプトを残さず、必要なら版のみを記録する。
- 既定は学習用 LLM が保存価値判定と要約・変更案生成を行う方式とする。任意の Jev 事前判定は、同意・認可・秘密除去後に構造化された候補有無のみを判断し、Memory 本文や Summary は既存の学習用 LLM に生成させる。Jev を OpenAI のモデル名差し替えとして扱わず、接続・credential・送信先の同意・上限を要件と設計で先に決める。
- Jev の不確実・不可・結果不明時の扱いを定義する。明示的な記憶依頼、訂正、既存記憶の変更を見逃さない経路を設ける。代替推論も再認可・上限を通し、無制限の再試行や結果不明な作用の自動再実行をしない。
- 両方式で形成・更新・訂正・想起抑制、出所・根拠 Summary・消去境界・秘密除去を検証する。小話、記憶依頼、訂正、秘密を含む会話を比較し、見逃し、API 回数、実測費用を確認してから既定方式の変更を判断する。費用削減を事前の前提にしない。

## L3: 対象指定の訂正境界（対象指定 caller の追加前）

現行 formation に内包された訂正は、[Interface Boundaries の H-C](../../design/concrete/interface-boundaries.md) にある独立した `ProposeCorrectionCommand` / `CorrectionOutcome` と型が一致しない。設計の優先順位に従い、対象指定 caller の導入前に、H-C の分離を実装するか、現行 formation を正とする設計変更を行うかを決める。訂正と状況変化、expected revision による stale、消去・制約による hold の意味を保ち、古い形成結果で新しい認識を上書きしない。変更した境界のテストで確認する。
