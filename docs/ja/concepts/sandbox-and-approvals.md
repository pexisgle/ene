# サンドボックス・Broker・承認

このページでは、Ene がプラグイン・サイドカー・stdio MCP サーバー・ダウンロードしたコードを、触れてはいけないものに触れさせない仕組みを説明します。従来のプラグインごとのアドホックな権限に代わる 3 層を扱います。

1. **OS サンドボックス** — プロセスにはホストが許可したものだけが見える
2. **Broker チャネル** — OS へのアクセスはすべてホストが仲介する
3. **承認モデル** — 要求できる上限(Manifest 層)と、実際に許可される範囲(ポリシー層)

## 原則

- プラグイン・サイドカー・stdio MCP・ブラウザは、すべて同じ Artifact・Broker・リソース管理下に置かれる
- プラグインに socket・DNS・HTTP クライアント・Cookie 保存領域・API キーを直接渡さない。必要な操作は Broker 経由でホストに依頼する
- ユーザーファイルの読み書きは `File` Broker 経由のみ。プラグインへ生のパス権限は渡さない
- 自動許可は確認ダイアログを省略するだけであり、署名・hash・サイズ・接続先・サンドボックス・リソース制限の検証は無効化されない
- 後方互換性は維持しない。新しい manifest・IPC・Broker へ一括移行する

## OS サンドボックス

Linux で有効化されたプラグインは次の制約のもとで起動します:

- **Landlock** — ファイルシステムの許可リスト。読み取り/実行はバイナリ・システムライブラリ・CA ルート・assets・Artifact のみ。書き込みはプラグイン専用 temp ディレクトリ・IPC socket・書き込み許可済みフォルダのみ
- **`no_new_privs` + seccomp** — 権限昇格と危険なシステムコール(`mount`・`ptrace`・`bpf`・`keyctl`・`setns`・`unshare`・`open_by_handle_at`・io_uring 等)をブロック
- **rlimit** — ファイルディスクリプタ数・アドレス空間・ファイルサイズ・CPU 時間・コアダンプ
- **cgroup v2**(任意、委譲された cgroupfs が必要)— プロセスツリーのメモリ・pids・CPU を制限
- **ネットワーク名前空間**(任意、特権が必要)— プラグインに直接のネットワークを一切与えず、すべて `Network` Broker 経由にする

Windows では有効化されたプラグインは **Job Object**(終了時 kill・プロセス数・メモリ・CPU 時間の制限)に入り、サスペンド状態で生成 → Job へ割り当て → 再開されます。AppContainer / Low Integrity への強化は次のステップとして文書化されています。

すべての層は fail-closed です。必須の層を初期化できなければプラグインは起動しません。特権が必要な層(cgroup・ネットワーク名前空間)は既定で無効で、提供できるホストでのみ明示的に有効化します。

プラグイン別のサンドボックス設定は `plugins.list.<name>.sandbox`、全体の既定は `plugins.sandbox` にあります。純粋な計算系の同梱プラグイン(`calc`・`counter`・`random`)と、Broker 移行済みの同梱プラグイン `web`・`fs`・`git`・`edge-tts`・`openai`・`anthropic`・`openai-tts`・`elevenlabs`・`geo`・`utility` は既定で**有効**です。残りの同梱プラグインは Broker チャネルへの移行が完了するまで既定で無効です。有効化した場合、カーネルが要求層を適用できないと起動を拒否します。

`web` プラグインは `Network` Broker 経由で通信しています(SSRF・リダイレクト処理はホスト側へ移行済み)。`fs` プラグインはユーザーファイルの読み書きと shell 実行をすべて `File` / `Process` Broker 経由に移行済みです。ツールの引数は絶対パスのままで、ホストが `plugins.list.<name>.fs_grants` の許可フォルダに正規化パスが含まれるかで解決します。`openai`・`anthropic` プラグインは全 API リクエストを `Network` Broker 経由で行い、API キーはホストが通信時に注入します(下記「資格情報の注入」参照)。

## Broker チャネル(プロトコル v8)

ホストサービスソケットは `db`・`capability` に加えて次の passenger を多重化します:

| Passenger | 仲介する内容 |
|---|---|
| `file` | 承認済み論理スロット内の読み書き・削除・移動・一覧、ダウンロード保存 |
| `network` | origin 承認・リダイレクト再検証・SSRF ブロック付き HTTPS 取得、ホスト temp 領域へのダウンロード |
| `process` | タイムアウト・出力上限・暗黙ダウンロード禁止(`npx -y`・`uvx`・`npm install` 等)付き子プロセス |
| `credential` | ホスト管理の資格情報。監査ログにはキー名のみ記録 |
| `artifact` | 署名 Catalog の解決・インストール・1 世代ロールバック |
| `platform` | 時刻・ロケール・外部 URL を開く |
| `websocket` | `ws://` / `wss://` セッション(接続時に origin 承認・SSRF アドレス固定・資格情報注入) |
| `db` / `capability` | 既存の型付き DB CRUD とプラグイン間呼び出し |

ID は認証トークンに固定されるため、プラグインが他のプラグインのセッションを開くことはできません。プラグイン側は `ene-plugin-broker` クライアントで、ホスト側は `ene-plugin-host` で実装されています。

### 資格情報の注入

API キーはプラグインプロセスに渡りません。プラグインはネットワークリクエスト上でホスト管理の資格情報を名前で指定し(`NetworkFetch` / `NetworkFetchStream` の `credential: "api_key"`)、ホストが自身の状態(`plugins.list.<name>.credentials`、または同梱 provider プラグインでは解決済みの `ai.providers.<kind>.api_key`)から値を解決して `CredentialUse` カテゴリを判定し、送信リクエストへ注入します。既定は `Authorization: Bearer <value>`(OpenAI)で、`credential_header` で指定すれば Anthropic の `x-api-key` のようなカスタムヘッダーにも注入できます。プラグインが見られるのはキー名のみで、監査ログにもキー名だけが記録されます。ホストが保持しない資格情報を指定したリクエストは、ネットワーク処理の前に失敗します。プラグイン自身が送る authorization 系ヘッダーは除去されます。

## Manifest 層

すべてのプラグインは署名付き manifest(`PluginManifest`)を持ち、以下を宣言します:

- 論理 FS スロット(`workspace`・`media` 等)— 実パスは記録しない
- 固定接続先(正確な `https://host[:port]`)
- `dynamic_web`(任意の公開サイトへのアクセスを*要求できる*か)
- 必要な Artifact・サイドカー(Catalog の ID + バージョン条件)
- 開けるホストサービス
- 宣言された side effect とリソース上限
- 要求できる許可カテゴリとその最大モード

metadata にない権限は、自動許可設定があっても要求できません。同梱プラグインの manifest はホストバイナリに内蔵され、構成上信頼されます。サードパーティ製は `plugins.trusted_publishers` の公開鍵で署名検証されます。

## 承認層

ホスト側ポリシーが、*宣言済み*の要求に対して何をするかを決定します:

1. **強制セキュリティ制約** — 署名・hash・サイズ・SSRF・パス包含。違反は常に拒否
2. **プラグイン別上書き** — 全体ポリシーより優先
3. **全体ポリシー** — カテゴリごとの既定値(`Ask`)
4. **`Ask`** — 対話確認。ヘッドレス環境では安全側(拒否)に倒れる

全カテゴリの初期値は `Ask` です。高危険度カテゴリ(ファイル作成・変更・削除、HTTP、LAN、Artifact インストール/更新、プロセス起動、shell、ブラウザ、資格情報)を自動許可にすると設定画面に常時警告が表示され、初回は二段階確認が必要です。**緊急停止**は全要求を拒否し、**リセット**はすべて `Ask` に戻します。

設定画面の **承認** ページには、全体ポリシー表・プラグイン別上書き・高危険度警告・緊急停止・リセット・監査ログパスが表示されます。自動許可を含むすべての決定は監査ログ(`app_data/audit/plugin-approval.jsonl`)に、プラグイン・カテゴリ・対象・適用ルール・結果として記録されます。秘密・本文・ファイル内容は記録されません。

## ダウンロード

Web 閲覧用ダウンロードと実行可能 Artifact のインストールは完全に分離されています:

- **Web ファイル**はホストが temp 領域に取得し、最終 URL・種類・サイズ・SHA-256 を表示して毎回確認したうえで `FileBroker` が無害化した名前で保存します。自動実行・自動展開・自動上書きは禁止です。自動保存プリセットは、保存先・サイズ上限・競合規則を設定した場合のみプロンプトを省略できます。
- **実行可能 Artifact**(プラグイン・サイドカー・モデル)は署名付き Catalog からのみ取得します。TUF 風のメタデータ(Ed25519 署名・期限・rollback 保護)、CAS(SHA-256)ストレージ、`Range`/`ETag` による再開ダウンロード、atomic な活性化と 1 世代ロールバックを備えます。更新は `artifact_id + version + digest + max_bytes` 単位で承認が必要で、同一バージョンの digest 変更・期限切れ Catalog・署名不正・rollback・サイズ超過は自動許可に関係なく拒否されます。

## SSRF ガード

`Network` Broker は loopback・プライベート IP・link-local・クラウド metadata(`169.254.169.254`)・CGNAT・マルチキャスト・予約アドレスをブロックし、ホストを毎回解決して接続先を検査済みアドレスに固定します(DNS rebinding 対策)。リダイレクトは各ホップを再検証し、ホップごとに origin 承認を要求します。平文 HTTP は警告付きの別承認となり、資格情報は注入されません。LAN アクセスは v1 では拒否されます。
