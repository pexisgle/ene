# 長期記憶システムとハイブリッド想起

Ene の長期記憶アーキテクチャは、セッションを越えた永続的な想起、型付きメモリの分類、ハイブリッド検索スコアリング、およびバックグラウンド記憶整理を提供します。

---

## 1. 型付きメモリの分類

`ene-store` 内の記憶は `MemoryKind`（`Episodic`, `Semantic`, `UserProfile`, `Relationship`, `Affective`, `Commitment`, `Preference`, `Procedure`, `WorldState`, `Reflection` の全 10 種）により型付けされます。対話コンテキストで利用される主な分類は以下の通りです：

| メモリ型 | スコープ | 具体例 |
|---|---|---|
| **エピソード (Episodic)** | 出来事の記録・対話サマリー | *"ユーザーは金曜日に Rust のゲームエンジン構築について話した。"* |
| **セマンティック (Semantic)** | 一般的ファクト・知識 | *"ユーザーは VSCode より Neovim を好む。"* |
| **プレファレンス (Preference)** | 嗜好・嫌悪・習慣 | *"深煎りコーヒーが苦手。"* |
| **コミットメント (Commitment)** | タスク・約束・合意事項 | *"明日の午前10時にデプロイログを確認すると約束した。"* |

---

## 2. ハイブリッド想起アルゴリズム

`before_turn` の実行時、 `ene-mind` は `ene-store` に候補の*収集* (ベクトル・字句・新近・コミットメントの検索) を依頼し、その候補を `ene-rag` に渡して多要因 **ハイブリッド検索スコア** で*スコアリング*します：

$$S = w_v \cdot S_{\text{vector}} + w_l \cdot S_{\text{lexical}} + w_r \cdot S_{\text{recency}} + w_s \cdot S_{\text{salience}}$$

各シグナルの定義：
- **$S_{\text{vector}}$**: `sqlite-vec` を使用した埋め込みベクトルのコサイン類似度。
- **$S_{\text{lexical}}$**: 全文検索 BM25 マッチスコア。
- **$S_{\text{recency}}$**: 作成時からの経過時間に基づく指数減衰スコア。
- **$S_{\text{salience}}$**: 記憶抽出時に割り当てられた重要度ランク。

### MMR (Maximal Marginal Relevance) 多様化
プロンプトパケットに重複したファクトが注入されるのを防ぐため、候補記憶は MMR リランクを通されて多様性が最大化されます。

### アクセス bump ポリシー
記憶が想起されると、その `access_count` と `last_accessed_at` が bump されます — ただし、**実際にプロンプトへ載った場合に限ります**。予算マネージャは、トークン予算を超過した際に、想起された記憶のセクション全体を削除したり、セクション内で切り詰めたりすることがあります。そのような記憶は検索では想起されたもののモデルからは一切見えないため、bump *されません*。パッキングを生き残った記憶の集合は追跡され (`PromptPacketMeta::injected_memory_ids`)、合成後にそれらのみが bump されます。これにより「検索では上位だったが削除された」ことが記憶を強化するのを防ぎます (#345)。

bump がランキングに与える効果も制限されています。アクセスブーストは最終アクセスからの経過時間で減衰する (半減期減衰) ため、ずっと前のアクセスはカウントされなくなり、記憶が永続的なランキング上の優位を固定することはできません。

## 3. コミットメント台帳

コミットメント（Ene が行った約束やユーザーからの依頼）には特別なアトミック性が与えられます：

- **単一の真実のソース**: コミットメントエンティティは厳格な状態 (`Active`, `Fulfilled`, `Cancelled`, `Expired`) で管理されます。
- **台帳の保護**: 約束したタスクの失念を防ぐため、アクティブなコミットメントはプロンプト構築時に最優先で挿入されます。

---

## 4. バックグラウンド整理と忘却サイクル

ターンレイテンシを低く保つため、記憶の書き込みは非同期に処理されます：

1. **同期的なターン完了**: ターンが終了すると、即座に `EneEvent::Terminal` が発行されます。
2. **遅延記憶抽出**: バックグラウンドタスクがターンのトランスクリプトを検査し、候補ファクトを抽出し、ベクトル埋め込みを生成して SQLite に保存します。
3. **忘却と減衰**: 低重要度の記憶はスコアが自然減衰し、保持ルールに従ってアーカイブまたは削除されます。

### 忘却のアンカー
忘却の減衰は、記憶が最後に想起された時 (`last_accessed_at`) ではなく、最後の**内容更新** (`updated_at`) を基準に測定されます。想起の新近性 (候補のランキングに使う) は引き続き `last_accessed_at` を使いますが、この2つは意図的に分離されています。記憶が想起されたことで、自身の忘却の時計をリセットできてはならないためです。もしリセットできれば、頻繁に想起される記憶はフェード閾値に決して到達せず、想起が記憶のスコアを*上げると同時に*忘却からも守るという自己強化ループが生じます (#345)。記憶の内容を編集すれば `updated_at` が更新されて正当に生き延びますが、単に想起するだけでは生き延びません。
