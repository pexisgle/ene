# ターンとセッション

## ターン

**ターン**は会話の 1 単位です。ユーザーメッセージ（またはプロアクティブ・
スケジュールによるトリガー）と、それに対するシステムの一連の応答を指します。

### ターンの ID と並行性

- すべてのターンは `TurnId` を持ちます。
- `EneHandle::run` は即座に `TurnId` を返し、ストリーミングイベントは
  イベントバスに届きます。
- ターン実行は**単一実行（single-flight）**です。別のターンが実行中なら
  `run` は `RunError::Busy` で失敗します。`cancel(&turn_id)` で実行中ターンを
  中断できます（ID が古いと `CancelError::TurnMismatch`）。

### ターンの起点（origin）

| 起点 | トリガー |
|---|---|
| `user` | 送信したメッセージ |
| `proactive` | キャラクターが自発的に話すと判断（プロアクティブパイプライン） |
| `scheduled` | 永続スケジュールが発火（[スケジュール](../guides/schedules.md)参照） |

### ターン内部で起きること

1. `before_turn` — 感情の減衰・想起計画 + ハイブリッド検索・
   キャラクター/lorebook 同期・プロンプトデータのプリフェッチ。
2. プロンプトパケットの構成 — セクション化されたシステムプロンプト +
   予算化された履歴。
3. LLM ストリーミング — テキスト差分・ツール呼び出し・パフォーマンスキュー。
4. 途中のツール — 権限ゲート付き実行。ツールが質問する場合はユーザー入力
   プロンプト。
5. 確定 — 感情提案・セッション状態の更新。
6. 履歴コミット + `Terminal` イベント。その後バックグラウンドでメモリ抽出。

完全なパイプラインは
[認知ランタイム](../reference/architecture/cognitive-runtime.md) にあります。

## イベント

ランタイムは**3 つの独立したチャネル**を公開します。トラフィックの種類が
互いを枯渇させないためです:

| チャネル | 内容 | 消費方法 |
|---|---|---|
| チャットバス | `EneEvent`: ターンライフサイクル・テキスト差分・ツール呼び出し/結果・権限要求・パフォーマンスキュー・ビートパルス | ブロードキャスト、`subscribe()` |
| ライフサイクルバス | `LifecycleEvent`: ステータス変更・保留候補通知・バックグラウンドツール完了 | ブロードキャスト、`subscribe_lifecycle()` |
| 音声ストリーム | `AudioChunk`（再生用 TTS 音声） | 単一コンシューマ、`take_audio_stream()` |

チャット/ライフサイクルイベントには安定した JSON ミラー
（`PublicChatEvent`・`PublicLifecycleEvent`）があります — 外部クライアント向け
です（[API v1](../reference/architecture/api-v1.md)参照）。

## セッション

**セッション**は 1 人のキャラクターとの連続した会話で、`SessionId` で
識別されます。履歴・メモリの由来・要約を整理するために存在します。

- セッションは、明示的に分割されたとき、アイドルタイムアウト
  （`mind.session.session_timeout_minutes`）が経過したとき、またはトピック
  境界検出器が会話の変化を判断したときに終了します。
- セッション終了時、会話は**要約**され、その要約は以降のセッションの
  キャラクターコンテキストの一部になります。
- セッションは一覧・エクスポート（バージョン付き・リダクション済み JSON）・
  インポート・検索・アーカイブ・アーカイブ解除ができます — CLI の
  `/session` コマンドか API v1 のセッションメソッドで。

## コンテキスト圧縮

履歴がモデルのコンテキスト窓を超えそうなとき、ランタイムは圧縮します。
古いメッセージはローリング「アクティブシーン要約」にまとめられ、最近の
メッセージはそのまま残ります。イベントバスが `context_compressed` を発行する
ため、クライアントは何が起きたか表示できます。圧縮はプロアクティブに
（設定可能な待機時間つきで）トリガーされるため、ターンが途中で待たされる
ことはありません。

## Undo

アクターは状態変更操作（権限付与・メモリ編集・スケジュール変更）の undo
スタックを保持します。`EneHandle::undo` / `/undo` は直前の操作を取り消し、
何を取り消したかを報告します。
