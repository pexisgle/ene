# コネクタ

コネクタは**外部サービス連携**のためのフレームワークです。カレンダーや
GitHub、Discord など、キャラクターが操作できるサービスを指します。
フレームワークは `ene-connector` にあり、個々の連携は `Connector` トレイトを
実装するプラグインです。

## フレームワークが提供するもの

- **`Connector` トレイト + レジストリ** — 共通ライフサイクル: 登録・接続性
  チェック・接続/切断・アクションごとの権限付与・ステータススナップショット。
  すべての操作はコネクタのタイムアウトポリシーと、デフォルト拒否の権限
  ゲートの下で実行されます。
- **コネクタ ID** — 安定した `namespace.name` 形式の ID
  （`ConnectorId`）、設定 UI 用の表示メタデータ（`ConnectorIdentity`）、
  OAuth スコープ（`PermissionScope`）。
- **安全な資格情報ストレージ**（`CredentialStore`）— OAuth2 トークンと
  API キー。シークレットは `Debug`/`Serialize` からリダクションされ、
  drop 時にゼロ化されます。生データの唯一の出口は監査付きの
  `expose_for_persistence` パスです。
- **`PermissionGate`** — フェイルクローズのアクション別承認。ターン単位の
  付与と会話単位のアクションパターンをサポートします。
- **トランスポートポリシー** — タイムアウト・指数バックオフのリトライ・
  レート制限・ページネーションヘルパー（HTTP 連携向け）。
- **Webhook 検証** — 受信 webhook の HMAC 署名 + リプレイウィンドウ検証。
- **資格情報宣言** — プラグインが必要な資格情報を宣言し
  （`x-ene-credentials`）、`ene-plugin-host` が起動時にスコープ付きアクセスへ
  解決します。
- **リダクション** — イベント・監査・エラー境界での構造的シークレット除去。

## プラグインとの関係

`ene-connector` は意図的に `ene-config` と `ene-plugin-proto` に依存しません。
プラグインバイナリが設定/プロトコルの重みを引きずらずに資格情報型を使える
ためです。`ene-plugin-host` が両者の間に立ち、コネクタ世界とプラグイン世界の
両方を知っています。

## コネクタとの操作

- **デスクトップ** — 設定 → コネクタページでコネクタ状態を確認し、
  アカウントを接続/切断できます。
- **CLI** — `/connector <list|status|check|connect|disconnect|grant|revoke|permissions>`。
- **ランタイム** — `EneHandle::connectors()` が `ConnectorHandle` を返し、
  コネクタ状態の変化は `LifecycleEvent::ConnectorChanged` としてブロードキャスト
  されます。

## 例: カレンダーツール

`plugins/tool/calendar` がコネクタ消費側の参照実装です。複数のカレンダー
アカウントを管理し、スコープ付き権限を要求し、アクション（イベントの
一覧/作成/更新/キャンセル・空き時間検索）を承認ゲートを通して実行します。

コネクタ状態の変化はライフサイクルバスに通知されるため、UI はポーリング
なしで更新できます。
