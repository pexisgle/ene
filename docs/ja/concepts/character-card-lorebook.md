# キャラクターカード・ロアブック

CCv3 キャラクターカードには **ロアブック**（`character_book`）— トリガーとなる
`keys`・`content`・任意フラグを持つワールド情報エントリの集合 — を同梱できます。
このページでは、Ene がロアブックエントリをどうマッチさせ、CCv3 の `@@`
デコレータをどう解釈するかを説明します。

## エントリのマッチング

エントリは次の条件で選択されます:

- `constant: true`（常に選択）**または**
- `keys` の少なくとも 1 つが直近の会話（`scan_depth` 以内）にマッチし、
  `@@exclude_keys` のいずれにもマッチしない;
- `selective` / `secondary_keys` は CCv3 仕様どおり:
  `selective` 指定時は `secondary_keys` の少なくとも 1 つもマッチする必要があります;
- 有効な `@@` デコレータの条件がすべて満たされている（下記参照）。

マッチングは部分文字列一致で、デフォルトでは **大文字小文字を区別しません**
（`case_sensitive: true` で区別します）。日本語など空白区切りでない言語のキーも
部分文字列一致で動作するため、`ドラゴン` は `ドラゴンが現れた` にマッチします。
`use_regex: true` の場合、キーは正規表現として扱われ、コンパイルできないキーを
持つエントリは決してマッチしません。

> `@@additional_keys` について: 仕様は「これらの値のうち少なくとも 1 つが
> 存在すること」と定義しています — メインの `keys` に積み重ねる AND 条件であり、
> 「全てがマッチしなければならない」わけではありません。Ene は仕様に従います。

## 注入

デコレータ行は、コンテンツを保存・注入する前に `content` から除去されます。
生の `@@…` テキストがプロンプトに漏れることはありません。

キー一致・`constant` エントリは、プロンプト構築時に **確定注入** されます。
想起パイプラインの外で処理されるため、他のメモリとのスコア競合・MMR 多様化・
セクション生存競争に巻き込まれることはありません。専用のプロンプトセクション
として描画されます:

- `position: "before_char"`（または `@@position before_desc`）→ キャラクター
  説明の**前**に置かれるセクション;
- `position: "after_char"`（デフォルト）および `@@position after_desc` →
  キャラクター説明の**後**に置かれるセクション。

どちらのセクションも required です: 予算パッカーが落とすことはありません。
セクション内の並びは `insertion_order` 順（小さい方が先。同順はカード順）。

### トークン予算

`token_budget` は注入されるエントリ全体（セクションと深さ配置メッセージの
両方）のトークン総量を制限します。超過時は仕様どおりの順序でエントリを落とし
ます:

1. `@@ignore_on_max_context` のエントリを最優先で;
2. 次に `priority` 昇順（未設定なら `insertion_order` にフォールバック）;
3. 次に `insertion_order` 昇順。

`constant: true` のエントリは**決して落とされません** — カードの常時注入契約
です。`token_budget` 未設定なら、マッチした全エントリがサイズに関わらず注入
されます。`@@ignore_on_max_context` が効くのは `token_budget` が設定された
ときだけです: 予算がなければ何も削られないため、フラグ付きエントリも他と
同様に注入され続けます。

### 深さ配置

`@@depth N` は直近メッセージから数えて `N` 番目の位置に履歴メッセージとして
注入し、`@@reverse_depth N` は最古メッセージから数えます。履歴長を超える深さは
最古メッセージの前に置かれます。メッセージのロールは `@@role` で決まります
（デフォルト `system`）; セクション配置の場合はシステムブロック内です。
深さはモデルが実際に見る履歴（予算トリム後）に対して解決されます。

### スティッキー発火

`@@keep_activate_after_match` と `@@dont_activate_after_match` は実状態で
動作します: あるエントリは、セッションのそれより前のターンで受理されていれば
「過去にマッチした」とみなされます（そのターンのアシスタント数でキー・フィルタ・
ゲートを評価）。状態は保持されているセッション履歴から導出されるため、マッチ
したターンが履歴内にある間は有効です（圧縮で消える可能性はあります）。

## デコレータ一覧

デコレータは `content` の先頭行に配置します（コンテンツ内のどこでも機能し、
注入前に除去されます）。

### 発火制御

| デコレータ | Ene の挙動 |
|---|---|
| `@@activate_only_after N` | アシスタント（キャラクター）メッセージ数が `N` に達するまでマッチしない。`N = 0` はゲート無効。 |
| `@@activate_only_every N` | アシスタントメッセージ数が `N` で割り切れるときのみマッチ。`N <= 1` はゲート無効。 |
| `@@keep_activate_after_match` | 一度マッチしたら以後常にマッチ（スティッキー）。 |
| `@@dont_activate_after_match` | 一度マッチしたら以後マッチしない。 |
| `@@activate` | 無条件でマッチさせる（`@@dont_activate` を上書き）。 |
| `@@dont_activate` | マッチさせない（`@@activate` がなければ）。 |

スティッキーデコレータ（`keep_activate_after_match` /
`dont_activate_after_match`）は注入パイプラインで実状態を持ちます。状態は
セッション履歴から導出されます（[スティッキー発火](#スティッキー発火) 参照）。

### 配置

| デコレータ | Ene の挙動 |
|---|---|
| `@@depth N` | 直近メッセージから数えて `N` 番目の位置に履歴メッセージとして注入（ロールは `@@role`）。`N < 1` はプリフィルを意味しますが、Ene はプリフィル非対応のため高優先度位置（`position` によるセクションの先頭）にフォールバックします。 |
| `@@reverse_depth N` | 同様に、最古メッセージから数えます。 |
| `@@instruct_depth N` | **パースのみ・無視** — Ene はチャットベースであり、仕様はチャット文脈でこのデコレータを無視するとしています。 |
| `@@position after_desc\|before_desc\|personality\|scenario` | `before_desc` → キャラクター前セクション、`after_desc` → キャラクター後セクション。`personality` / `scenario` は仕様どおり無視（Ene は personality/scenario を独立セクションに持たず、アイデンティティカーネルに統合）; その場合は `position` フィールドが配置を決めます。 |

### スキャン

| デコレータ | Ene の挙動 |
|---|---|
| `@@scan_depth N` | このエントリに限りロアブックの `scan_depth` を上書き。`recursive_scanning` 時は、上書きの有無に関わらず他エントリの内容はマッチ対象に残ります（spec 準拠）。 |
| `@@instruct_scan_depth N` | **パースのみ・無視** — チャット文脈（`@@instruct_depth` 参照）。 |
| `@@is_greeting N` | セッションのアクティブな挨拶インデックスが `N` のときのみマッチ（`0` = `first_mes`、`i+1` = `alternate_greetings[i]`）。挨拶未選択時はデコレータを無視し、`@@@` フォールバックチェーンを適用（仕様の「アクティブな挨拶を判定できない場合」に該当）。 |

### フィルタ

| デコレータ | Ene の挙動 |
|---|---|
| `@@additional_keys A,B,…` | 値のうち少なくとも 1 つがスキャン窓に現れる必要がある（`keys` に積む AND 条件）。複数回指定可能。`use_regex` に従います。 |
| `@@exclude_keys X,Y,…` | いずれかの値が現れたらエントリを抑制。`use_regex: true` の場合は無視（仕様どおり）。 |
| `@@is_user_icon name` | **パースのみ・無視** — Ene にユーザーアイコンのプロンプト機能はありません。 |

### メタ

| デコレータ | Ene の挙動 |
|---|---|
| `@@role assistant\|system\|user` | 深さ配置メッセージ（`@@depth` / `@@reverse_depth`）のロールを設定します。デフォルトは `system`。 |
| `@@ignore_on_max_context` | 注入エントリが `token_budget` を超えたとき最優先で落とされます（[トークン予算](#トークン予算) 参照）; 予算未設定時は無効です。 |
| `@@disable_ui_prompt post_history_instructions\|system_prompt` | **パースのみ・配線なし** — 有効化するとカードが Ene の感情表現出力契約を無効化できてしまうためです（コアの製品保証）。 |

## フォールバックチェーン（`@@@`）

未知のデコレータはスキップされますが、直後の **フォールバック**（`@@@name`
行）が代わりに上から順に検討されます。チェーンは任意の長さにできます:

```
@@risu_only_decorator 4
@@@agn_only_decorator 4
@@@activate_only_after 4
```

チェーン内のどの要素も認識できなければ、グループ全体が無視されます
（コンテンツからは除去されます）。同名デコレータは**最初の 1 つだけ**が有効です —
ただし仕様で複数回の使用が許されている `@@additional_keys` を除きます。
