# キャラクターカードのアセットとインポート

CCv3 カードは `data.assets` で外部アセット（VRM モデル、VRMA モーション、アイコン、背景など）を宣言できます。このページでは、Ene がアセット宣言をどう消費するか、対応する URI スキーム、PNG / CHARX カードのインポート方法を説明します。

## 宣言アセット（`x_vrm` / `x_vrma`）

仕様はアプリ固有アセット型に `x_` 接頭辞を予約しています。Ene が消費するのは:

- `x_vrm` — 3D アバターとして使う VRM 1.0 モデルファイル;
- `x_vrma` — デスクトップ UI で選択できる VRMA モーションクリップ。

それ以外の型（`icon` / `background` / `emotion` など）はパースのみで、まだ消費しません。他ツール製カード向けに、接頭辞なしの `vrm` / `vrma` 表記も受け付けます。

カードが `assets` を宣言している場合、デスクトップの発見処理はその宣言から VRM / モーションパスを解決します（宣言順を維持）。ディスク上に存在しない宣言アセットはスキップされ、デスクトップ UI に警告として表示されます。`assets` を持たないカードは従来どおり、キャラクターフォルダー内の拡張子スキャン（再帰、シンボリックリンクは辿らない）で発見します。モーションの優先順は `extensions.ene.motion_catalog` → `x_vrma` アセット → 拡張子スキャンです。

## URI スキーム

`assets[].uri` は、ファイル操作に影響を与える前に必ず 1 つのリゾルバ（`resolve_asset_uri`）で検証されます。対応スキーム:

- `embeded://path/to/file` — 仕様のスペル（パスは大文字小文字を区別、`/` 区切り）。カードディレクトリからの相対パスとして解決します。トラバーサル（`..`）、絶対パス、ドライブプレフィックス、バックスラッシュ、パーセントエンコーディングは拒否します。入力側では一般的な誤表記 `embedded://` も許容します。
- `ccdefault:` — その型のアプリ既定アセット（同梱の `AliciaSolid.vrm` / `VRMA_01.vrma`）。
- `http://` / `https://` — 検証してリモート参照として解決します。発見時はスキップされ（マテリアライズされるまで再生できないため）、インポートではダウンロードせず URI を保持します。
- `data:` — base64 またはパーセントエンコードのインラインペイロード。発見時はスキップし、インポート時にサイズ上限付きでデコードして `assets/{type}/3d/` に書き出し、カードの URI を `embeded://` に書き換えます。
- スキームのない値は、非仕様プロデューサとの互換性のため埋め込み相対パスとして扱います。

未知のスキーム（`file://`、`ftp://` など）は仕様の MAY-ignore ルールに従って無視され、カード自体は読み込み可能なままです。

## PNG カード（`ccv3` / `chara`）

PNG カードはカード JSON をテキストチャンクに埋め込みます。Ene は `ccv3` チャンク（V3、base64 JSON）を読み、無ければ旧 `chara` チャンク（V2、base64 JSON）にフォールバックして V3 形状にラップします。tEXt（非圧縮）に加え、zTXt / iTXt（deflate 圧縮）にも対応し、base64 を省略した素の JSON も許容します。Chub.ai / JanitorAI のカードはこの経路で読み込めます。

## CHARX カード

CHARX アーカイブはルートに `card.json` を持つ zip で、アセットは内部に格納されます。展開前にエントリ名を検証します（トラバーサル・絶対パス・シンボリックリンク・暗号化エントリを拒否、エントリごと・合計のサイズ上限あり）。アーカイブがキャラクターフォルダーの外に書き出すことはできません。

## インポート

`ene characters import <パス>`（または REPL の `/import <パス>`）で PNG / CHARX カードを `characters/{カード名}/` フォルダーとして展開します:

- PNG → `character.json`（`ccv3` / `chara` チャンク由来）と `avatar.png`（元画像。`ccdefault:` アイコンが実ファイルを指すため）;
- CHARX → 全体を展開し、`card.json` は `character.json` にリネーム;
- `data:` の `x_vrm` / `x_vrma` アセットはデコードして `assets/{type}/3d/` に書き出し、カードの URI を `embeded://` に書き換え;
- 安全でないアセット URI（トラバーサル・絶対パス）はインポートを拒否;
- 既存フォルダーは上書きせずインポートを拒否。

インポート後は通常のキャラクターフォルダーになるため、次回スキャンでデスクトップや `ene characters list` から発見されます。`load_character_card` と `/card` は、インポートせずに PNG / CHARX ファイルを直接読むこともできます。
