# 認知ランタイム

`ene-mind` は認知エンジンです。LLM を発話の生成器とみなし、性格・記憶・
感情・行動はエンジンが管理する明示的な状態とします。このページでは
パイプラインを詳細に説明します。

## コンポーネント

`CognitionEngine` は次のものを合成します:

| コンポーネント | 責務 |
|---|---|
| `ContextManager` | コンテキスト窓のトークン予算・ローリング圧縮・シーン要約 |
| `RecallPlanner` | ターンの意図 → 検索計画（スコープ・種別・予算） |
| `MemoryRecallCache` | メモリ想起の L1 インメモリキャッシュ（L2 は `ene-store`） |
| `MemoryWriter` | ターン後の抽出（決定的 + LLM）と仲裁 |
| `EmotionEngine` | PAD 感情: 減衰・決定的更新・任意の LLM 分類器 |
| `CharacterProcessor` | アイデンティティカーネルコンパイル・lorebook インデックス/注入 |
| `PromptPacket` | セクション化されたプロンプト構成 |
| `OutputArbiter` | 表情/モーションの検証・ヒステリシス・キュー選択 |
| `CommitmentLedger` | 約束/タスク追跡とプロンプト注入 |

エンジンはデータベースに直接触れません。`ene_core::MemoryPort`
（ベクトルは `EmbeddingStorePort`）に対してプログラミングするため、
SQLite なしでユニットテストできます。

## ターンパイプライン

### 1. `before_turn`

- キャラクターの `AffectState` を読み込み、現在時刻まで減衰
  （valence/arousal/dominance・trust・affinity・irritation・curiosity・
  fatigue）。前ターンの保留中分類器提案があれば適用。
- 新メッセージから想起を計画: 意図を検出（ユーザー・世界・過去の出来事に
  ついての質問か…）、スコープ/種別と予算を選択。
- ハイブリッド想起を実行: ベクトル類似度（埋め込みがある場合）・語彙
  オーバーラップ・新しさ・感情一致・関係スコア・矛盾/陳腐化ペナルティ。
  多様化（MMR）してアクセス回数を増加。
- プロンプトに必要なものをプリフェッチ: アイデンティティカーネル
  （時刻/シーン/関係段階の行付き）・保証 lorebook エントリ・シーン要約・
  アクティブ約束・ワークスペースチャンク。

### 2. プロンプト構成

プロンプトは**セクション**として固定の描画順で組み立てられます:

```text
プラットフォーム契約
Lorebook（キャラ前）
アイデンティティカーネル   ← キャラクター定義。コンテキスト窓の 1/8 に
                            予算化（400..4000 トークンにクランプ）
Lorebook（キャラ後）
キャラクター状態           ← 感情/機嫌の要約
シーン状態                 ← ローリング要約
セマンティックコンテキスト  ← lorebook + キャラクターメモリ
ユーザープロフィール       ← ユーザー/関係/好みメモリ
ワークスペースコンテキスト  ← 検索されたドキュメントチャンク
アクティブ約束
エピソードメモリ
文体例
中断ノート                 ← 中断された応答の後だけ
出力契約                   ← 表情 PHI・NG フレーズ
ユーザー入力               ← 現在のターン
```

セクションはモデルの有効コンテキスト窓（プロバイダー公表窓から応答予約と
安全マージンを差し引いたもの）に詰められます。履歴が溢れそうなときは、
古いメッセージがシーン要約へ圧縮されます
（[ターンとセッション](../../concepts/turns-and-sessions.md#コンテキスト圧縮)参照）。

### 3. ストリーミングとツール

トークンはプロバイダーからストリーミングされ、途中のツール呼び出しは権限
ゲート付きでランタイムが実行します。対話型ツールはユーザーに質問するため
ターンを一時停止できます。パフォーマンスキュー（expression/motion/lookat）
はモデルまたは感情エンジンが要求したときに発行されます。

### 4. `after_turn` / 確定

- 感情エンジンが**感情提案**を生成（決定的更新 + 有効時は LLM 分類器）。
  提案は保留として保存され、次ターン開始時にマージされます。応答が
  ストリーミング途中で再描画されることはありません。
- 会話履歴がストアにコミットされ、`Terminal` イベントでターンが閉じます。
- **遅延処理**: メモリ抽出+仲裁・忘却パス・自己内省はターミナル後に
  バックグラウンドで実行され、ユーザーがメモリ処理を待つことはありません。

## 感情モデル

感情は **PAD**（快-覚醒-支配）と関係指標です:

- `valence`（-1..1）・`arousal`（-1..1）・`dominance`（-1..1）
- `trust`・`affinity`（-1..1）— ユーザーとの関係
- `irritation`・`curiosity`・`fatigue`（0..1）
- `mood_label`・`last_expression`・離散感情強度

値はカードの `affect_baseline`（未指定なら全ゼロ）に向かって時間とともに
減衰します。`AffectState` はキャラクターごと（任意でユーザーごと）です。

## メモリライターと仲裁者

ターン後、`MemoryWriter` が実行します:

1. 決定的抽出（約束・ユーザー明示の事実・ツール接地）。
2. 分類モデル設定時は LLM 抽出。
3. `MemoryArbiter` の判断: 意味的重複検出（埋め込み類似度 + 正規化タイトル
   フォールバック）・矛盾処理（新メモリが旧メモリを置換）・確信度/重要度
   スコアリング・`mind.memory_approval.require_approval` 時の承認キュー保留。

結果は `MemoryWriteOutcome` として報告されます（成功、または保留キュー ID
付きのリトライ/恒久失敗）。

## プロアクティブ発話

プロアクティブパイプラインは、キャラクターが自発的に話すかどうかを判断します:

- **決定的ゲート** — クールダウン・最小アイドル時間・静音時間（曜日別
  スケジュールと抑制ポリシー付き）・疲労抑制・一時停止フラグ。
- **ソース** — 会話・アクティビティ・画面要約・メモリ・ウィンドウタイトル
  （設定可能なレベル）。
- **判断 LLM** — ゲート通過後、軽量モデル呼び出しで話すか・何を話すかを
  決定（緊急度スコアと `SILENT_TOKEN` オプション付き）。
- **ワールド状態** — 任意の環境スナップショットで傾向検出
  （「1 時間アイドルでした」）。
- **保留確認** — 確認待ちの約束は最低経過日数後に再提示できます。

プロアクティブターンは `TurnOrigin::Proactive` で実行され、完全に無効化
できます（`mind.proactive.enabled = false`）。

## 出力仲裁

`OutputArbiter` はアバターに届くすべてのパフォーマンスキューを検証します。
表情はモデルに存在し、モーションはカタログに存在しなければならず、
ヒステリシス/レート制限でちらつきを防ぎます。キューのソースは `affect`
（感情エンジン）か `llm`（モデルの明示的要求）で、優先度で競合を解決します。

## 要約

セッション境界で `summarize_conversation` が要約を生成し、キャラクターの
継続コンテキスト（`SceneState`）の一部になります。長期間のコンパニオンでも
会話の筋を忘れません。

## 境界

- `ene-mind` は `ene-runtime` と `ene-plugin-host` に依存しません。
- 永続化には `ene_core::MemoryPort` 経由でのみアクセスします。
- `ene-store` は dev-dependency のみ（結合テスト用）です。
