# ツール用データベースプロキシ仕様 (`ene-tool-db`)

`ene-tool-db` クレートは、サンドボックス環境で動作する独立したツールバイナリが、ホストプロセス上の SQLite データベースに対して、型安全かつセキュアにデータ保存・読込（CRUD操作）を行うためのソケットクライアントおよび通信メッセージプロトコルを提供します。

---

## 1. データベース接続 & 認証プロトコル

ツールはホストから環境変数経由で渡された `db_socket` および `db_auth_token` を用いて、専用ソケットへ接続し、ハンドシェイクを行います。

### 1. 通信メッセージ定義 (`DbRequest` / `DbResponse`)

#### `DbRequest` (ツール → DBサーバー)
*   **`Handshake`**:
    -   `auth_token`: ホストが発行した認証トークンを Blake3 でハッシュ化した値。
    -   `tool_name`: 送信元のツール識別子。
*   **`DeclareSchema`**: `DbSchema` 定義（テーブル一覧、インデックス、カラム型情報）を登録。
*   **`Insert`**: レコード（`Row`）の挿入要求。
*   **`Update`**: レコードの更新要求。フィルタ条件 `DbFilter` に合致する行を書き換えます。
*   **`Delete`**: レコードの削除要求。
*   **`Select`**: クエリ実行要求。`filters`, `order_by`, `limit`, `offset` を指定。

#### `DbResponse` (DBサーバー → ツール)
*   **`HandshakeAck`**: 認証成功応答。
*   **`Success`**: 操作成功。更新件数や、最後に挿入された RowID を含みます。
*   **`Rows`**: `Select` クエリの結果（レコードのリスト）。
*   **`Error`**: エラー情報（`DbErrorCode` とエラーメッセージ）。

---

## 2. プレフィックスによるセキュリティ境界 (Table-Name Prefix Isolation)

任意のSQL実行をツールに許可すると、ツールが他のプラグインやシステム本体の記憶テーブル（例: `typed_memories`）を破壊・盗聴する危険が生じます。これに対処するため、データベースサーバーはテーブル名に対するプレフィックス分離を強制します。

*   **名前空間ルール**:
    ツールが `DeclareSchema` で宣言するすべてのテーブル名は、手動で指定された `DbSchema::prefix`（例: `my_tool_`）から開始される必要があります。
*   **サーバー側検証ガード**:
    `DbIpcServer` は、受信した `Insert` / `Update` / `Select` などのすべてのリクエストに対し、対象テーブル名が指定されたプレフィックスで開始されているかを検査します。プレフィックスから外れたテーブル名（例: `typed_memories` 等）へのアクセスが検知された場合、SQLを一切構築せずに即座に `DbErrorCode::PermissionDenied` を返して処理を遮断します。

---

## 3. ASTベースのセキュアな SQL 生成

SQLインジェクション脆弱性を完全に防ぐため、本プロトコルは生のSQLクエリ文字列の送信を禁止しています。

*   **構造化クエリ**:
    ツール側は、フィルタ条件を `DbFilter` 構造体（カラム名、演算子 `Eq` / `Like` 等、パラメータ値 `DbValue`）としてシリアライズして送信します。
*   **パラメータバインド**:
    ホストサーバーは受信した構造化データをパースし、安全にパラメータがバインドされた（Prepared Statement）SQLを内部で動的構築して実行します。また、カラム識別子やテーブル名自体も `^[A-Za-z_][A-Za-z0-9_]*$` の正規表現でサニタイズされた安全な文字列のみがSQLに差し込まれます。
