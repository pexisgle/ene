# ツールセマンティック検索仕様 (`ene-tool-rag`)

`ene-tool-rag` クレートは、LLMに入力するツールプロンプトのサイズを最適化するため、ユーザーのクエリ文脈に関連性の高いツールのみを動的に選択するツールRAG（Retrieval-Augmented Generation）パイプラインの実装を担当します。

---

## 1. データ構造

### `FieldWeights` (公開 / 構造体)
ツールが持つ複数の特徴メタデータ（マルチベクトル）に対する類似度の重み付け定義。
*   `summary: f32`: ツールの概要の重み（デフォルト: 1.0）。
*   `description: f32`: ツールの動作詳細説明の重み（デフォルト: 0.6）。
*   `capability: f32`: ツールができる能力記述の重み（デフォルト: 0.8）。
*   `example: f32`: 使用例の重み（デフォルト: 0.4）。
*   `negative: f32`: **ネガティブマッチに対するペナルティの重み**。ツールが「してはいけない動作（アンチパターン）」に一致した場合にスコアを引き下げます（デフォルト: -0.5）。
*   *(注)*: LLM を用いた仮想ドキュメント埋め込み（`HyDE`）は非推奨・無効化（no-op）されています。

---

## 2. ツール選定フロー

`ToolRag::select` は、以下のパイプラインに沿ってツールを判定・選定します。

1.  **クエリのベクトル化**:
    -   ユーザーの最新の発話テキストを `EmbeddingProvider::embed` に投入し、特徴ベクトルを生成。
2.  **マルチベクトル類似度検索**:
    -   `MemoryStore` の `tool_embedding_index` テーブルから、現在ロードされている全ツールのベクトルインデックスをロード。
    -   各ツールに対し、定義されている複数のフィールド（Summary, Description 等）ごとにクエリベクトルとのコサイン類似度を算出。
    -   設定された `FieldWeights` を乗算して合算し、ツールの総合関連度スコアを計算。
3.  **関連度しきい値フィルタリング**:
    -   総合スコアが `min_similarity`（デフォルト: 0.25）未満のツールは選定プールからドロップ。
4.  **強制ロード（Forced Tools）のマージ**:
    -   RAGの検索スコアに関わらず、システムが常時必要とするツール（例: `utility.question`（会話継続用問合せ）, `utility.get_current_time`（現在時刻取得））を強制的に最終結果に差し込みます。
5.  **カテゴリ制限の適用 (`per_category_limits`)**:
    -   同一種類のツール（例: ファイル操作ツール）ばかりがプロンプトを占有するのを防ぐため、カテゴリキー（`fs`, `web` 等）ごとに最大出現数を切り詰めます。
6.  **最終カットオフ (`final_n`)**:
    -   総合スコア順にソートされた結果から、上位 `final_n`（デフォルト: 6）個のツール仕様（`ToolSpec`）を取り出し、LLMのプロンプト構築用に返却します。
