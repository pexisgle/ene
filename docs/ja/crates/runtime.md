# `ene-runtime`

> **クレート**: `ene-runtime` | **役割**: アクターベースのホストファサード & ターンエンジン

`ene-runtime` は Ene を組み込むアプリケーション (`ene-cli`, `ene-desktop`) のメインエントリポイントです。スレッドセーフなファサードである `EneHandle` を所有し、ターンの実行、プロンプト構築 (`ene-mind`)、記憶永続化 (`ene-store`)、プラグイン監視 (`ene-plugin-host`)、およびツール DB IPC ソケットサーバーを統合管理します。

---

## アーキテクチャ境界

- `EneHandle` の公開メソッドはすべて、単一スレッドのアクター (`handle::actor::TurnActor`) への非ブロッキングなチャネル送信または oneshot 非同期リクエストです。共有可変状態に直接触れることはありません。
- 読み取り専用のセッション/候補クエリと画面画像のビジョン要約は、アクターのメールボックスを完全にバイパスして `ene-store` やビジョンモデルに直接アクセスします。ターン実行コマンドとアクターのスループットを奪い合いません。
- 小さな毎フレーム状態はメールボックスフリーの共有スロットへミラーリングされます (#407): `EneHandle::card_name()` / `session_id()` / `session_started_at()` / `turn_count()` / `config()` / `character_card()` はそれぞれ1つの `parking_lot` ロック (またはアトミック) を取るだけで、アクターがミューテーション時点 (セッション分割、`SetCharacter`、ターンごとの簿記、機能設定更新) に同期するスロットを読み取ります — egui イミディエイトモードから安全に呼べ、実行中の `Run` ターンの背後に並ぶことはありません。大きな履歴ペイロードだけはメールボックス経由のままで、専用の `EneHandle::history()` が提供されます。
- ツール操作 (`list` / `search` / `call` / `invalidate`) は専用ハンドル `EneHandle::tools()` を持ちます (#406) が、意図的にアクターメールボックスに留まります。ツール呼び出しと検索はそこ (Stage 8) でアドミッション制限され (`EneRuntimeError::Busy`)、レジストリはプラグインホスト再構成時に差し替えられるアクター所有の状態だからです。読み取り専用ハンドルとは異なり、`ToolHandle` は API 形状の分割であり、転送のバイパスではありません。
