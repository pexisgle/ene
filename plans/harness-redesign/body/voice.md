# 全二重音声パイプライン

> 実現する要件: **P-102**(全二重音声)、**P-103**(割り込みの音声側)、
> P-111(翻訳再生、後継)。パイプラインは**コアデーモン所有**(確定済み決定)。

## 1. 所有と配置

- マイクロフォン・スピーカー・VAD・ASR・TTS のすべてをコアデーモンが
  所有する。クライアント(特に Web・将来のモバイル)は音声フレームを
  ストリーミングするだけ。これにより、別デバイスからの会話や、
  複数クライアントで同じ「声」を共有できる。
- desktop はローカルオーディオデバイス入出力をコアへ中継する役割
  (cpal 相当の取得/再生)。Web はブラウザの MediaStream を WS で中継。
- 音声エンジン(VAD/ASR/TTS)はプロバイダプラグイン。
  VAD は [../plugins/ipc.md §4](../plugins/ipc.md#4-ストリーミング音声など高頻度データ)
  の専用チャネル。ASR/TTS の制御は同文書 §3.3。ローカル/クラウドを問わない。

## 2. パイプライン

```text
入力側:
 mic/WS フレーム → 前処理(エコーキャンセリング相当・ゲイン)
   → VAD(発話区間検出) → ASR(partial 逐次 → final)
   → inbox の wake(user/message として昇格)

出力側:
 発話テキスト確定 → TTS(ストリーミング合成)
   → 音声チャンクを再生キューへ(クライアントへ配信)
   → body へリップシンク同期([body-and-performance.md §3](body-and-performance.md#3-発話との同期リップシンク))
```

- ASR の partial は**内面側に見せない**(ノイズ)。final のみ昇格。
- TTS は文単位で区切り、先頭チャンクの遅延を最小化する
  (目標: テキスト確定から 500ms 以内に発声開始、ローカル目安)。

## 3. 全二重の要件

- **発話中も聴き続ける**: 出力再生中も入力は VAD に掛かり続ける。
- **自声回避**: コアが再生中の音声と入力フレームを照合し、
  自己発話をユーザー発話として拾わない。手段は
  (a) 再生区間のマスク、(b) エコーキャンセラ(クライアント報告)の
  組合せ。ヘッドホンなしでの使用を想定する。
- **バグイン**: 再生中にユーザー発話を検知したら即座に割り込み
  (§4 の状態機械)。

## 4. 割り込み状態機械(P-103)

```text
IDLE ──ユーザー発話検出──► LISTENING ──final確定──► THINKING
 ▲                                                    │
 │                                                    ▼
SPEAKING ◄──────TTS 先頭チャンク────────── RESPONDING
 │
 └─バグイン(再生中のユーザー発話検出)─► INTERRUPTING
        ├─ TTS 再生を即停止(全クライアント)
        ├─ 進行中ターンを interrupted で確定(core/agent-loop.md §10)
        └─ 新たな発話を LISTENING として受理
```

- `INTERRUPTING` はデバウンス付き(300ms)。短い相槌(「うん」)は
  割り込みにしない(最小発話長 0.4 秒、`voice.barge_in.min_speech_ms`)。
- 割り込まれた発話の「中断位置まで」はセッション履歴に残る。
- 割り込みの連続(ユーザーが立て続けに遮る)は感情側に記録し、
  疲労の材料にできる([../companion/soul-and-affect.md §4](../companion/soul-and-affect.md#4-更新規則))。

## 5. 音声のセッション記録

- ユーザー音声入力は、ASR final テキストを `user/message` として
  記録し、元音声は artifact 参照として添付(既定: 保持しない、
  `voice.keep_raw_audio = false`。保持は opt-in)。
- コンパニオンの音声は TTS の生成物であり、ログにはテキストのみ
  残す(音声の再生再現はしない)。

## 6. 複数体の調停(P-405 対応)

- 複数コンパニオンが同時にいる場合、音声出力は**1体ずつ**
  (同時発話はしない)。再生キューは先着順で、
  割り込みは「現在発話中の体」へのバグインとして扱う。
- 入力音声は「話しかけられた体」へのルーティングが課題になるが、
  v1.0 では**アクティブ体**(ユーザーが選択/UI で前面)への送付を既定とし、
  発話者の識別(誰に話しているか)は後継(M3/M5 参照)。

## 7. 翻訳再生(P-111, 後継・接点のみ)

- 発話テキストと TTS 入力が分離しているため、間に翻訳を挿す接点が
  既にある(`tts_input_transform`)。v1.0 では実装しない。

## 8. 設定キーと既定値

| キー | 既定 | 説明 |
|---|---|---|
| `voice.enabled` | `true` | 音声機能全体 |
| `voice.barge_in.enabled` | `true` | バグイン |
| `voice.barge_in.min_speech_ms` | `400` | 割り込みとみなす最小発話長 |
| `voice.vad.provider` | `auto` | VAD プロバイダ |
| `voice.asr.provider` | `auto` | ASR プロバイダ |
| `voice.tts.provider` | `auto` | TTS プロバイダ |
| `voice.keep_raw_audio` | `false` | 元音声の保持 |
| `voice.input.routing` | `active_body` | 入力ルーティング(後継で `speaker_id` 追加) |

## 9. 障害モード

| 障害 | 挙動 |
|---|---|
| マイク不在/権限なし | テキスト対話に退化+通知。音声入力は無効化 |
| ASR プロバイダ不能 | ローカルフォールバックがなければテキスト入力へ退化+警告 |
| TTS の遅延(2秒超) | 先頭チャンク待ちの表示(内面で「考え中」)、会話はテキストで先に確定 |
| 自声の誤検出(自分の声を拾う) | 再生マスクの強化(再生区間±200ms の入力破棄) |
| WS 音声の途切れ(Web) | 途切れ区間を欠損として扱い、partial を確定しない。3秒超の途切れで LISTENING を終了 |
