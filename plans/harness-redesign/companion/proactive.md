# 能動発話

> 実現する要件: **P-105**(能動発話)、**P-106**(静寂の同居)、
> P-306(疲労・quiet hours のゲート入力)。
> スケジュール発火は **P-606 の所有者**
> ([../tasks/jobs-and-schedules.md](../tasks/jobs-and-schedules.md) §3)であり、
> このパイプラインの入力ではない。

ユーザー発話なしにコンパニオンが起こすターン。
airi/OLV の proactive speech を、Ene のゲート+決定+発話の3段で設計する。

## 1. パイプライン

```text
監視(常時・軽量)
  ├─ 会話の途切れ・ユーザーの活動(入力・ウィンドウ・任意の画面要約)
  ├─ コネクタの受信イベント(calendar 変更等)
  └─ 記憶/約束の再浮上(commitment の期限接近)
        ↓
ゲート(決定論・低コスト)
  ├─ クールダウン / 最小アイドル時間
  ├─ quiet hours(曜日別時間帯+抑制ポリシー)
  ├─ 疲労(soul-and-affect.md の fatigue)
  └─ 一時停止フラグ(ユーザーが「静かにして」)
        ↓
決定(軽量モデル・任意)
  └─ 話すべきか/何を話すか(SILENT 選択肢あり)
        ↓
発話(TurnOrigin::Proactive のターン)
```

スケジュール/リマインドの発火は `TurnOrigin::Scheduled` であり、
このパイプラインを通らない。発火と quiet hours の繰り下げは
[../tasks/jobs-and-schedules.md §3](../tasks/jobs-and-schedules.md#3-スケジュールp-606)
が所有する。二重ゲートしない。

- **ゲートは必ず決定論**で、コストのかかる判断はゲート通過後のみ。
- **決定モデル**は `ai.tasks.proactive`(安価なモデル推奨、ローカル可)。
  決定を無効化すると、ゲート通過=発話になる(簡素モード)。
- 発話は対話レーンの通常ターンとして走り、履歴・記憶・感情の
  全経路がユーザー発話と同一。

## 2. ゲートの詳細

| ゲート | 既定 | 説明 |
|---|---|---|
| クールダウン | 30 分 | 前回の能動発話からの最小間隔 |
| 最小アイドル | 15 分 | ユーザーが無操作になってからの時間 |
| quiet hours | 23:00-07:00 | 抑制ポリシーは `silent`(一切話さない)/ `important`(リマインドのみ)の2択、既定 `silent` |
| 疲労抑制 | fatigue 0.7 以上 | 話しかけ頻度を半減(クールダウン2倍) |
| 一時停止 | ユーザー操作 | 「静かにして」で明示解除まで停止 |

## 3. ソースと優先度

| ソース | 内容 | 優先度 |
|---|---|---|
| `commitment_due` | 約束の期限接近・確認待ちの再浮上 | 高 |
| `conversation` | 会話の途切れ・未完の話題 | 中 |
| `activity` | ユーザーの活動変化(長時間の作業・離席からの復帰) | 中 |
| `memory` | 記憶の想起(「そういえば」) | 低 |

スケジュール発火は上表に無い。`TurnOrigin::Scheduled` として
jobs-and-schedules が直接ターンを起こす。

- 複数のソースが同時に成立する場合は、優先度の高い1つを採用し、
  残りはキュー(次回以降)。キューの保持は 24 時間。

## 4. 世界状態(任意・後継の接点)

- 環境のスナップショット(時刻・活動・任意の画面要約)を「世界状態」と
  して持ち、傾向検知(「もう1時間も作業してるね」)の材料にする。
- v1.0 では**時刻と活動のみ**。画面要約は vision seam 次第(後継、
  [../tools/capabilities.md §9](../tools/capabilities.md))。

## 5. 静寂の同居(P-106)

- 能動発話が起きない時間は「不在」ではなく「同居」として扱う。
- body は静寂中でも最小限の生命感を持つ: 瞬き・呼吸・軽い視線移動、
  ユーザーの大きな入力への軽い反応(顔を向ける等)。
  これらはターンを起こさない **body の自律アニメーション**であり、
  感情状態を弱く反映する([../body/body-and-performance.md](../body/body-and-performance.md))。
- 静寂の長さ自体を内面チャネルに記録しない(ノイズの抑止)。

## 6. 設定キーと既定値

| キー | 既定 | 説明 |
|---|---|---|
| `mind.proactive.enabled` | `true` | 全体の有効性 |
| `mind.proactive.cooldown_min` | `30` | クールダウン |
| `mind.proactive.min_idle_min` | `15` | 最小アイドル |
| `mind.proactive.quiet_hours` | `23:00-07:00` | 曜日別に上書き可能 |
| `mind.proactive.quiet_policy` | `silent` | `silent\|important` |
| `mind.proactive.decision_model` | `auto` | `ai.tasks.proactive` を使用 |

## 7. 障害モード

| 障害 | 挙動 |
|---|---|
| 決定モデルの失敗 | ゲート通過分を簡素モードで発話(決定をスキップ)。失敗はライフサイクル警告 |
| quiet hours 中の能動発話 | `silent` は抑制。`important` はリマインド相当のソースだけ通す。スケジュール発火の繰り下げは jobs-and-schedules 側 |
| クールダウン中のユーザー発話 | 能動発話を抑制(ユーザー発話が優先) |
| 対話レーン塞がり | 能動発話はキューへ。塞がりが長い(10分)場合は破棄 |
