# 完成の定義

> 「何が揃えば完成と言えるか」を定義する唯一の文書。
> 機能 ID は [features.md](features.md) に従う。位置づけは [vision.md](vision.md)。

## 構造

- **ビジョン**: プロダクトの到達点(この文書の §2)。段階に依存しない。
- **v1.0 = 完成**: 観察可能な受入条件で定義する。これを満たせば「完成した」と
  宣言できる。
- **後継マイルストーン**: 完成定義の外だが、形式が支える機能群。
- **非目標**: やらないこと。

## ビジョン(到達点)

ユーザーのデバイスに、**複数の AI コンパニオン**が住んでいる。

コンパニオンはそれぞれ独立した人格と感情を持ち、音声とテキストで全二重に
会話できる。記憶も基本は独立だが、ユーザー自身についての知識は全員が共有する。
入力は表層の soul が受け、簡単なことはその場で片付け、複雑な作業だけ裏層の
ハーネスへ託す。両層はメッセージで進捗を共有し、ユーザーからは1体として
見える。何も頼まれなければ、たいていは静かに寄り添い、
重要なことが起きたときだけ自分から話しかける。

すべてはユーザーのデバイスで完結し(ローカルファースト)、ツール実行は
サンドボックスと承認ポリシーに守られている。キャラクターはパッケージとして
配布・交換でき、ユーザーは soul と body を自由に組み替えて自分だけの
コンパニオンを作れる。

## v1.0 = 完成

`[x]` は、Echo / Scripted / Placeholder 以外の経路、または実プロセスで
観察できる項目に限る。機構検出(テストダブル・ホスト API の直接呼び出し・
ランチャー起動)は [w7-verification.md](w7-verification.md) の「機構」列に
残し、完成宣言には使わない。

### 総括条件

次の状態が**同時に**成り立つとき、v1.0 は完成である。

1. [x] desktop(stage)+ CLI + Web の3クライアントが、同一のコアデーモンに
   接続して使える。
2. [ ] 1体以上のコンパニオンが、以下の受入条件をすべて満たす。
   総括 3・裏層ジョブループ・本番音声が埋まるまで開けない。
3. [ ] ローカルモデル構成でネットワークなしに §受入条件 の会話が成立する
   (オフライン可)。`SeamedModel` の配線はある。受入テストは EchoModel
   往復のままで、設定済み provider での会話は未観測。
4. [x] Linux 開発機で `nix develop` からビルド・起動でき、
   [platform/process-model.md](../platform/process-model.md) が定める
   性能の観点(常駐時のメモリ・起動時間・軽量ツールの往復)で許容できる。
   具体的な数値は実装しながら決める(D-29)。
5. [x] 監査ログ・バックアップ・エクスポートのデータ保全系が動作する。

### P-1xx 会話と存在感の受入条件

- [ ] 話しかけると、**発話を遮って**割り込める。遮られた応答は中断として
      記録され、続きを話せる(または自然に新しい話題に移る)。
      正弦波 TTS/ASR のステートマシンのみ観測。本番 `VoiceRuntime` は
      `scripted()` のまま(P-102 / P-103)。
- [ ] コンパニオンの声に自分の声が混ざらない(自声回避)。正弦波 RMS 相関のみ。
- [x] テキスト入力でも同じセッションに会話でき、音声とテキストの履歴が
      1つのセッションログに統合される。ログ統合は実ストア。応答本文は Echo。
- [x] 内面(思考・感情表出)が**表層UIには出ず**、エクスポート既定にも出ない
      (D-20)。表層に出す設定は無い。ライブの内面演出は無い。
- [ ] 詳細画面から内面・thinking・層間メッセージを製品 UI として読める
      (P-712)。Web の Detail は JSON ダンプ。desktop もログ寄り。
- [ ] 放置しても、ほとんどの場合は何も起きない。重要なイベントが起きたときだけ
      能動発話がある(D-14)。ゲート fail-closed と無効化は実コード。
      「話すか」判定は `ScriptedClassify`(P-105 / P-524)。
- [ ] 2体のコンパニオンが stage に**同時に表示**され、それぞれと別々の会話が
      できる(D-6)。boot は occupant を2つ seed する。実 VRM の同時表示と
      別セッション会話の stage E2E は未観測(P-107 / P-405)。
- [x] セッションはアイドルタイムアウトと明示分割でのみ区切れる。話題が変わっても
      勝手に分割されない(D-8)。一覧・検索・再開・エクスポートができる。

### P-2xx/P-3xx 記憶と感情の受入条件

- [x] アプリを再起動しても、ストアに書いた会話内容・記憶・約束が残る。
      抽出本体は正規表現(`"my name is "` 等)。補助 LLM の scope 判定は未配線。
- [x] 忘却要求で該当記憶が消え、削除が監査に残る。
- [ ] 数日の使用で、関係メトリクス(信頼・親密度)が応答トーンに反映される。
      PAD 減衰と信頼の蓄積は実ストア。トーンへの一貫した反映はキーワード
      positive/negative とスクリプト分類(P-209 / P-301–P-307)。
- [ ] 感情表出が表情・モーション・声のトーンに反映され、ちらつきがない。
      表情アービタと PAD 非露出は実コード。本番音声・実 VRM での観察は未達。
      内部状態は詳細画面の JSON 寄り表示でのみ見える(D-19)。
- [x] 共有記憶プールと private 隔離のストア契約がある(D-7)。
      片側への発話から自動抽出して他方が使う経路は正規表現と
      `ScriptedClassify`。
- [x] `memory.write_shared` が共有プールへ書き、監査に残る(P-212)。
      表層スキーマから `write_shared` は消える。
- [ ] 画面を「見て」もらう依頼が通り(ツール経路)、それとは独立に、
      何も頼まなくても画面の変化が能動発話の材料になっている(補助LLM 経路)。
      後者の観測結果が会話履歴を圧迫しない(D-16)。
      ツール経路とホスト観測は同じ `app.screenshot` の PNG を使う。
      `{available: false}` は未取得。要約は世界状態メモリのみ。
      既定 `screen_summary` はオフ(明示オプトイン)。

### P-4xx 身体と表示の受入条件

- [ ] stage に正規 VRM コンパニオンが表示され、発話にリップシンクし、
      感情で表情が変わり、視線と軽い仕草がある。
      minimal GLB の wgpu ロードと viseme ヒューリスティックはある。
      正規パッケージの stage 表示と本番 TTS 連動は未観測(P-401 / P-403 / P-404)。
- [x] soul と body をパッケージとして組み替えられる(互換性警告が出る場合は
      その旨表示)。
- [x] テキスト専用モードで、描画なしでも会話レーンが動く。

### P-5xx ハーネスの受入条件

- [x] テキスト入力は表層 soul だけが受け、裏層ハーネスへ直接届かない
      スキーマ面がある(P-522 / D-2)。副作用ツールは表層スキーマに出ない。
- [ ] 「今何時?」「さっき何て言ったっけ?」のような簡単な依頼が、委譲を
      起こさずその場で返る(D-1)。Echo はユーザー文を `ack:` するだけで、
      実モデルの簡易応答は未観測(P-503 / P-505)。
- [x] 表層に副作用のあるツールが1つも公開されていない(D-2)。
- [x] ステップ数超過または副作用ツール要求で自動委譲へ切り替わる機構がある
      (D-3)。モデル判断には依存しない。Echo は `tool_calls` を出さないため、
      テストが tool call を注入したときだけ観測される。
- [ ] 会話をしながら job を依頼すると、対話が途切れずに job が裏で進む。
      `delegate.start` は SQLite 行を作る。モデル+ツールのジョブランナーは
      無い(P-504 / P-519 / P-605)。
- [ ] job 実行中のキャンセル・追加指示・質問回答が、動いているランナーに届く。
      CRUD とホスト API 直接呼び出しはある。
- [ ] ユーザーが話しかけ続けている間、委譲の完了報告は割込まず、
      会話の切れ目で届く。報告文言の単体テストはある。本番音声ギャップは未配線。
- [x] 表層UIとエクスポート既定に thinking・ツール引数原文・ツール生出し・
      子セッション内容が乗らない(D-11 / P-520)。internal 委譲の存在は表層に出ない。
- [ ] 同じ情報が**詳細画面では見える**(P-712)。API は JSON を返す。
      閲覧 UX は未達。
- [x] 子の質問結合・24時間仮定進行・孫委譲の深さガード・internal 秘匿連鎖の
      ストア契約がある。観測はホスト API 直接呼び出し(P-509 / P-512)。
- [ ] 長時間会話がコンテキスト窓を溢れても、compaction で要点が残る(P-506)。
      現行 `compact` は先頭 2000 文字切り詰め。要約 LLM は呼ばない。
- [x] セッションログが `model-visible = logged` 不変条件の検証テストに通る。
- [x] セッションの任意時点から fork でき、元のセッションが無傷で残る。
- [x] 強制終了後の再起動で、開いていた turn/job が中断として確定し、
      自動 resume しない(D-5 / P-515)。沈黙のまま消えないことの報告は
      中断検出まで。作業を続けるランナーは無い。
      重複効果なしの再開は v1.0 では保証しない(P-525 は後継)。
- [x] ツール失敗と中断は文言が区別される。
- [x] LLM 使用量台帳が soul/セッション単位で残り、完全性テストに通る。
- [x] CLI の `ene debug spans` で直近スパンを閲覧できる。属性にプロンプト
      コンテンツが乗らないことが CI で検証されている。
- [x] ストレージ形式が変わったとき、連鎖マイグレーションで開ける。
      開いている job は中断として確定し、実行は再開しない。
      古いバイナリが新しい形式を開くと拒否される。

### P-6xx ツールと仕事面の受入条件

- [x] リマインドがスケジュールされ、quiet hours をまたぐ場合は繰り下げ、
      `important` は quiet hours 中でも発火する(P-606 / P-607)。
- [ ] 「このテーマで調べてしおりにまとめて」が裏層ジョブとして走り、
      調査と成果物交付まで完了する(P-608 / P-609)。
      Markdown 書き込みヘルパーはある。モデルも web 検索も呼ばない。
- [ ] MCP サーバーを1つ、プロファイル行への手書き設定で接続し、
      そのツールを対話から実行できる。ブリッジバイナリはある。
      W7 根拠はインメモリ `ScriptedMcp`(P-603 / P-604)。導線 UI は後継
      (P-616 / D-23)。
- [ ] skill を1つ導入し、該当する依頼で使われる(P-610)。
      `SKILL.md` のコピーと `skill.load` はある。会話コンテキスト組立には未接続。
- [ ] `fs` / `exec` と MCP の git で簡易なコーディング作業が完遂できる。
      `exec` は `fs` と別ポリシー(D-24)。ビルトイン本体は薄いスケッチ。
      git はスタブ(P-602 / P-612)。
- [x] 巨大なツール出力が spill され、brief が有界に保たれる。
- [ ] job の進捗と完了がコンパニオンの発話として届く(D-13 / P-615)。
      ホストが `progress` / `complete` を直接呼ぶと発話になる。
      ユーザー向け呼称「タスク」は契約としてある。

### P-7xx プラットフォームの受入条件

- [x] desktop を起動するとコアデーモンが自動起動し、stage が使える。
- [x] CLI からコアデーモンを直接起動し、テキスト対話・ツール一覧・
      セッション操作ができる。API 面の対等性。
- [x] Web から(同一 LAN の)コアに接続し、テキスト対話ができる。
      設定変更と記憶の削除は Web からはできない(D-31)。
- [ ] Web と desktop の詳細画面から、内面・thinking・タスク一覧・記憶を
      製品 UI として閲覧できる(P-706 / P-712)。API は JSON を返す。
      Web の Detail は文字列連結。desktop は別ウィンドウでログ寄り。
- [x] desktop が WebView を一切使っていない(D-21)。
- [x] 2つのクライアントが同一セッションに同時接続でき、排他資源
      (音声入力・承認応答)が調停される。
- [x] 設定変更(JSON/環境変数)が反映され、スキーマが自動生成される。
- [x] バックアップ取得と復元がデータ欠損なくできる。

### P-8xx キャラパッケージの受入条件

- [x] Ene 正規形式のパッケージをインストールし、soul を作れる。
- [ ] インストールした正規 VRM を stage に表示し、会話できる。
      パッケージ I/O はある。stage 表示の受入は minimal GLB。会話は Echo。
- [x] V3(PNG)カードをインポートし、正規形式へ変換して使える。
- [x] キャラをエクスポートし、別環境でインポートして再現できる。
- [x] soul 単独・body 単独のファイルを組み合わせて1キャラを作れる。

### P-9xx 安全とプライバシーの受入条件

- [x] プラグインがサンドボックス外へ出ていけない(Landlock 対応時に検証)。
- [x] ファイル書き込みツールが、承認ポリシーに従って自動実行/確認される。
- [x] 「次から確認しないで」でポリシーが追加され、次回から自動実行される
      (変更はユーザー確認+監査ログ付き)。
- [ ] AI 自動承認モードで、承認判断の理由が監査ログに残る(P-904)。
      本番 `ApprovalPlane` は `ApproveModel = None`。テストは `ScriptedAi`。
- [x] 資格情報がボールトに暗号保管され、プラグインプロセスの環境変数に
      平文キーが漏れない。
- [ ] ローカルモデル構成で、外部通信ゼロで会話・記憶・スケジュール・
      ローカルツールが動作する。会話経路の受入は EchoModel。

### P-10xx 拡張性の受入条件

- [x] プロファイル切り替えで起動プラグイン集合が変わる。
- [x] Rust 以外の実装言語で書いたダミーツールプラグイン(IPC 規約準拠)が
      登録・実行できる。
- [ ] ビルトインツールとサードパーティツールが**同じ API** に載っている
      (D-10 / P-1001)。`plugins/tool/*` は `BuiltinKind` ランチャー。
      本体は `ene-registry` のホスト側ライブラリ。
- [ ] ツールプラグインが provider 副プロトコルを知らなくてもビルドでき、
      provider 側にモダリティを足しても既存ツールが失効しない(D-22 / P-1009)。
      hello で provider を名乗らない handshake はある。capability 副プロトコル
      とバルク FD 転送は未実装。
- [x] プラグインがクラッシュしてもカーネルは生き残り、サーキットブレーカーが
      作動する。死んだ供給元のツールはスキーマ面から降り、Broker grant は
      回収される(D-32)。
- [x] プロファイル切替で、外した行の登録がホスト文脈に残らず、
      無関係な行とコアデーモンは再起動しない。
- [x] `requires` が満たされない行はエラーにせず待ち、循環は起動時に
      報告されて関係行が `inactive` のままになる。
- [ ] waterfall にプラグインが intercept/rewrite で登録できる(P-1007)。
      現行はカーネル `LoopHooks` への整数単体テスト。

## 後継マイルストーン

v1.0 の完了定義には含めないが、**形式が支える**(既存形式の破壊を強制しない)。

| マイルストーン | 内容 | 支える形式 |
|---|---|---|
| M1 モバイル | スマホアプリ。ホスト型かクライアント型かは未定。 | server-api・SDK・音声ストリーミング |
| M2 コミュニティ配信基盤 | キャラ・プラグインの一覧/ダウンロード/評価/更新と、署名による検証(D-26)。 | パッケージ配布仕様(署名を後から足せる形) |
| M3 高度な複数体 | 同室会話(P-114)、複数体の協調表示。 | セッションログの room 拡張、body 契約 |
| M4 デスクトップペット | 透過・最前面・クリックスルー常駐。 | stage の表示抽象 |
| M5 カメラ認知・Live2D | カメラからの認知(P-115)、Live2D body(P-408)。画面の認知は v1.0(P-112)。 | capability seam、body 形式の拡張性 |
| M6 メモリ暗号化 | 保存時暗号化(P-214)。 | ストア抽象 |
| M7 重複効果なしのクラッシュ回復 | 3ストア・effect sandwich・OperationState による、任意のクラッシュ位置からの再開(P-525、D-4)。 | v1.0 のログ形式(後付けを妨げない構造) |
| M8 MCP 接続導線 | 設定画面から代表的な MCP サーバーを選んで追加(P-616 / D-23)。 | プロファイル行の形式 |
| M9 ネイティブプラグインの HMR | バイナリ差し替えをプロセス建て直しなしで行う。 | ファイバー unload がホスト文脈を空に戻すこと(P-1010 / D-32) |

## 非目標

設計に含めないもの。将来の方針転換にはビジョンの改訂を要する。

- **マルチユーザー共有サーバー**: 1デバイス=1ユーザー。アカウント・チーム・
  権限管理は作らない。
- **VTuber 配信連携**: OBS 連携・コメント読み上げ・同接機能は対象外
  (個人のコンパニオンであり、配信ツールではない)。
- **モバイル/クラウド同期のホスティング事業**: ローカルファーストであり、
  同期サービス自体の提供は非目標(形式上の余地は残す)。
- **コーディング特化 UX**: IDE 統合・diff レビュー UI・worktree 管理など、
  コーディングエージェント専用 UI は作らない(ツールとしてのコーディングは持つ)。
- **独自 LLM の開発・配布**: モデルはプロバイダ経由で利用する。
