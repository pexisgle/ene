# プロセスモデル

> 実現する要件: **P-701**(コアデーモン)、**P-708**(設定システム)、
> **P-709**(バックアップ)、**P-1005**(プラグイン監督)。

## 1. コアデーモン(P-701)

- **唯一のホスト**。セッション・メモリ・ツール・プラグイン・音声を所有する
  常駐プロセス。desktop が起動し、開発/自動化では CLI が起動する。
- 単一バイナリ `ene-core` を出す(現行の ene-cli とは別物。
  CLI はクライアントになる、[clients.md](clients.md))。
- 2重起動の禁止: データディレクトリのロックファイルで排他。
  既存インスタンスがあれば、クライアントとして接続し直す。

### 起動シーケンス

```text
1. データディレクトリの確保とロック
2. 設定の読み込み(defaults → JSON → env、§4)
3. ストアのオープン(sessions.db / companions.db / audit.db)
   └─ integrity_check 失敗 → 起動拒否+復元提案
4. プロファイルの合成(plugins/manifest-and-profile.md §2)
5. プラグイン監督の起動 → 各行の spawn+ネゴシエーション
6. プロバイダ seam の確定(ai.tasks.* の解決)
7. soul のロード(companions.db)→ レーン/ループの準備
8. HTTP/WS サーバーの bind(server-api.md)
9. 準備完了の通知(desktop への ready イベント)
```

- 起動は**段階的に利用可能**にする: ストア+対話の準備ができれば
  対話を開始でき、プロバイダ/プラグインの遅延ロードは並行して行う。

## 2. アクター配置

Tokio のアクター構成(現行 ene-runtime の方式を発展)。

| アクター | 責務 | panic 隔離 |
|---|---|---|
| コマンド受付 | クライアント API の受付・検証 | あり |
| セッションライター | ログの単一書き込み([core/session-log.md §4](../core/session-log.md)) | あり |
| soul ループ × N | soul ごとにターン/ステップ駆動([core/agent-loop.md](../core/agent-loop.md)) | あり |
| ツールディスパッチ | レジストリ照合・パイプライン駆動 | あり |
| プラグイン監督 | spawn/ヘルス/再起動/サーキットブレーカー | あり |
| Broker | 資源仲介([plugins/broker.md](../plugins/broker.md)) | あり |
| 承認 plane | ポリシー評価・ポップアップ配信・キュー | あり |
| 音声パイプライン | VAD/ASR/TTS の編成([body/voice.md](../body/voice.md)) | あり |
| スケジューラー | schedules の発火監視 | あり |
| 背景作業(メモリ抽出等) | 低優先プールのタスク群 | あり |

- **panic 隔離**: 各アクターのコマンド処理は catch_unwind で包み、
  panic は診断イベントにして継続する(現行 release が `panic = "abort"` を
  付けない方針を維持)。1アクターの死が全体を道連れにしない。
- 背景作業は**低優先プール**(既定 2 ワーカー)に集約し、
  対話の遅延を防ぐ。

## 3. プラグイン監督(P-1005)

- 各プラグイン行を子プロセスとして spawn し、
  [ipc.md](../plugins/ipc.md) のネゴシエーションを行う。
- **ヘルス**: ping 間隔 15 秒、3回不達で死亡判定。
- **再起動**: 死亡時はバックオフ付きで再起動(1s/4s/16s)。
  同一原因で5回連続失敗 → **サーキットブレーカー**(行を無効化、
  ライフサイクルで報告、手動再起動まで停止)。
- **drain/shutdown**: コア終了時は全プラグインに drain → 猶予 → kill。
- プロバイダプラグインの死亡は、そのプロバイダを使うタスクの
  一時的な `provider_unavailable` を起こす(対話全体は止めない、
  [core/agent-loop.md §8](../core/agent-loop.md#8-ガードとエラー回復))。

## 4. 設定システム(P-708)

- 優先順: **defaults → JSON → 環境変数**(現行を維持)。
  ネストは `ENE_` プレフィックス+`__` 区切り。
- 設定は各ドメインが `define_config!` 相当の登録を持ち、
  スキーマを自動生成する(手動メンテしない)。
- **再起動不要の反映**: プロファイル/プラグイン集合・
  プロバイダ選択・承認ポリシー・quiet hours 等は
  設定変更イベントで反映。反映できない項目(データディレクトリ等)は
  明記して再起動を要求する。
- 設定の変更は監査ログに残す([security/approval.md](../security/approval.md))。

## 5. バックアップと復元(P-709)

- 対象: `sessions.db`・`companions.db`・設定 JSON・characters/plugins の
  メタ情報(実体は再配布可能なので任意)。
- 手段: SQLite の **online backup API** で整合性のあるコピーを
  `<data>/backups/<ts>/` へ。既定の自動バックアップ: 起動時+日次、
  保持 7 世代。
- 復元: コア停止 → 選択世代からの復元 → 起動。
  復元前に現行を `pre-restore` として退避。

## 6. 性能予算

軽量目標(設計原則1)を数値で固定する。

| 項目 | 目標 | 備考 |
|---|---|---|
| 起動(対話可能まで) | 2 秒以内 | 段階的起動により |
| 待機時メモリ(コア+1 soul、描画なし) | 300 MiB 以下 | プラグイン込み |
| 待機時メモリ(+ VRM 描画) | 800 MiB 以下 | クライアント側 |
| ターン開始(発話→初チャンク) | ローカル 1 秒以内 / クラウドはプロバイダ依存 | コンテキスト組立のオーバーヘッド 100ms 以内 |
| ツール呼び出しの IPC オーバーヘッド | 5 ms 以内(中央値) | MessagePack+ソケット |
| 音声の往復(発話終了→応答開始) | 1 秒以内(ローカル構成目安) | ASR/TTS の遅延を除いた編成分 |
| データ成長 | sessions.db: 10 万イベントで 500 MiB 以下 | 記憶 DB は memory.md §11 |

- 予算の超過は CI の簡易ベンチで検知(回帰の監視)。

## 7. 障害モード

| 障害 | 挙動 |
|---|---|
| 2重起動 | ロックで検知し、後発は接続切替。データ破損の余地を作らない |
| アクターの panic | 診断イベント+再起動(可能なもの)。不能なら該当機能の退化を通知 |
| プラグインの起動遅延 | 段階的起動で他機能を先行。遅延プラグインは準備でき次第参加 |
| ディスク満杯 | ストア書き込みエラー → 対話の停止+通知(データ保全優先) |
| 設定の不正 | 該当キーを defaults に戻して起動+警告(起動不能にしない) |
| バックアップ中のクラッシュ | online backup は整合コピーのみ残る。中途ファイルは起動時に掃除 |

## 8. 設定キーと既定値

| キー | 既定 | 説明 |
|---|---|---|
| `core.data_dir` | プラットフォーム標準のデータディレクトリ | 全永続化の根 |
| `core.backup.auto` | `true` | 自動バックアップ |
| `core.backup.retention` | `7` | 保持世代 |
| `core.background_pool.workers` | `2` | 背景作業ワーカー |
| `core.plugins.circuit_breaker.max_failures` | `5` | ブレーカー閾値 |
