# プロセスモデル

> 実現する要件: **P-701**(コアデーモン)、**P-708**(設定システム)、
> **P-709**(バックアップ)、**P-1005**(プラグイン監督)。

## 1. コアデーモン(P-701)

- **唯一のホスト**。セッション・メモリ・ツール・プラグイン・音声を所有する
  常駐プロセス。desktop が起動し、開発/自動化では CLI が起動する。
- 単一バイナリ `ene-core` を出す(現行の ene-cli とは別物。
  CLI はクライアントになる、[clients.md](clients.md))。
- 2重起動の禁止: データディレクトリのロックファイルで排他。
  既存インスタンスがあれば、クライアントとして接続し直す。

### 起動シーケンス

```text
1. データディレクトリの確保とロック
2. 設定の読み込み(defaults → JSON → env、§4)
3. ストアのオープン(sessions.db / companions.db / audit.db)
   └─ integrity_check 失敗 → 起動拒否+復元提案
4. プロファイルの合成(plugins/manifest-and-profile.md §2)
5. プラグイン監督の起動 → 各行の spawn+ネゴシエーション
6. プロバイダ seam の確定(ai.tasks.* の解決)
7. soul のロード(companions.db)→ 表層(対話レーン)と裏層(job レーン)の準備
8. **中断の検出と片付け**(D-5): 前回の異常終了で `running` のまま
   残ったセッション/job を洗い出し、一時ファイルを片付けて
   `interrupted` を確定する。未 claim の inbox はログから復元して見せ、
   `abandoned_interrupt` で閉じる。**自動再開はしない**
   ([../core/agent-loop.md §12](../core/agent-loop.md#12-中断の検出と報告p-515--d-5))
9. HTTP/WS サーバーの bind(server-api.md)
10. 準備完了の通知(desktop への ready イベント)
```

- 起動は**段階的に利用可能**にする: ストア+対話の準備ができれば
  対話を開始でき、プロバイダ/プラグインの遅延ロードは並行して行う。
- 中断の**報告**は起動シーケンスではなく、次の対話ターンで
  コンパニオンが話す形で行う(D-13)。起動時にダイアログは出さない。

## 2. アクター配置

Tokio のアクター構成(現行 ene-runtime の方式を発展)。

| アクター | 責務 | panic 隔離 |
|---|---|---|
| コマンド受付 | クライアント API の受付・検証 | あり |
| セッションライター | ログの単一書き込み([core/session-log.md §4](../core/session-log.md)) | あり |
| soul ループ × N | コンパニオンごとに表層/裏層のターン/ステップ駆動([core/agent-loop.md](../core/agent-loop.md)) | あり |
| ツールディスパッチ | レジストリ照合・パイプライン駆動 | あり |
| プラグイン監督 | spawn/ヘルス/再起動/サーキットブレーカー | あり |
| Broker | 資源仲介([plugins/broker.md](../plugins/broker.md)) | あり |
| 承認 plane | ポリシー評価・ポップアップ配信・キュー | あり |
| 音声パイプライン | VAD/ASR/TTS の編成([body/voice.md](../body/voice.md)) | あり |
| スケジューラー | schedules の発火監視 | あり |
| 観測 | 画面の継続取得と補助LLM による要約、世界状態メモリの更新([../companion/proactive.md](../companion/proactive.md)) | あり |
| 背景作業(記憶抽出・compaction 等) | 低優先プールのタスク群 | あり |

- **panic 隔離**: 各アクターのコマンド処理は catch_unwind で包み、
  panic は診断イベントにして継続する(現行 release が `panic = "abort"` を
  付けない方針を維持)。1アクターの死が全体を道連れにしない。
- **ハーネス機能ツールもアクター内で動く**(D-10)。記憶想起や委譲は
  ツールディスパッチから直接呼ばれ、IPC を経由しない
  ([../tools/registry.md §0.1](../tools/registry.md#01-ハーネス機能ツールホスト内))。
- **補助LLM の呼び出しは背景作業と観測に集約する**(D-15)。
  記憶抽出・画面要約・能動発話の判定・compaction はいずれも
  低優先プールで走り、対話レーンの応答を遅らせない。
  対話と同じ優先度で走らせると、数十秒ごとの画面要約が
  会話の初チャンクを待たせることになる。

## 3. プラグイン監督(P-1005)

- 各プラグイン行を子プロセスとして spawn し、
  [ipc.md](../plugins/ipc.md) のハンドシェイクを行う。
  副プロトコルごとの版が合わなければ、**その面だけ無効化**して
  接続を続ける(D-22)。ツールは使えるが TTS は使えない、という
  部分的な状態を監督は許容する。
- **ヘルス**: ping 間隔ごとの応答を監視し、連続不達で死亡判定。
- **再起動**: 死亡時は指数バックオフ付きで再起動。
  同一原因で規定回数連続失敗 → **サーキットブレーカー**(行を無効化、
  ライフサイクルで報告、手動再起動まで停止)。
- **drain/shutdown**: コア終了時は全プラグインに drain → 猶予 → kill。
- プロバイダプラグインの死亡は、そのプロバイダを使うタスクの
  一時的な `provider_unavailable` を起こす(対話全体は止めない、
  [core/agent-loop.md §8](../core/agent-loop.md#8-ガードとエラー回復))。

## 4. 設定システム(P-708)

- 優先順: **defaults → JSON → 環境変数**(現行を維持)。
  ネストは `ENE_` プレフィックス+`__` 区切り。
- 設定は各ドメインが `define_config!` 相当の登録を持ち、
  スキーマを自動生成する(手動メンテしない)。
- **再起動不要の反映**: プロファイル/プラグイン集合・
  プロバイダ選択・承認ポリシー・quiet hours 等は
  設定変更イベントで反映。反映できない項目(データディレクトリ等)は
  明記して再起動を要求する。
- 設定の変更は監査ログに残す([security/approval.md](../security/approval.md))。

## 5. バックアップと復元(P-709)

- 対象: `sessions.db`・`companions.db`・設定 JSON・characters/plugins の
  メタ情報(実体は再配布可能なので任意)。
- 手段: SQLite の **online backup API** で整合性のあるコピーを
  `<data>/backups/<ts>/` へ。自動バックアップは起動時+日次、世代保持。
- 復元: コア停止 → 選択世代からの復元 → 起動。
  復元前に現行を `pre-restore` として退避。

## 6. 性能予算

軽量目標(設計原則1)を守るための**監視項目**。数値そのものは実装しながら
決める(D-29)。ここで固定するのは「何を測るか」と「どの構成で測るか」で、
目標値は計測後に置く。

**測定の正は `minimal` プロファイル**
([../plugins/manifest-and-profile.md](../plugins/manifest-and-profile.md) の出荷プロファイル)。
`desktop` は描画・音声デバイスを含む別予算であり、`minimal` の未達を
desktop の数字で隠さない。

| 項目 | プロファイル | 備考 |
|---|---|---|
| 起動(対話可能まで) | `minimal` | 段階的起動が効いているかの指標 |
| 待機時メモリ(コア+1 soul、描画なし) | `minimal` | バンドル済みプラグイン込み |
| 待機時メモリ(+ VRM 描画) | `desktop` | クライアント側。`minimal` の対象外 |
| ターン開始(発話→初チャンク) | 両方 | プロバイダの遅延を除いた、コンテキスト組立の分 |
| ツール呼び出しの IPC オーバーヘッド | `minimal` | MessagePack+ソケット。音声のサイドチャネルはこの RPC 予算に入れない |
| 音声の往復(発話終了→応答開始) | `desktop` | ASR/TTS の遅延を除いた編成分 |
| 観測(画面要約)の常駐コスト | `desktop` | 継続観測が有効なとき、対話の遅延に影響していないか |
| データ成長 | 両方 | sessions.db のイベント数あたりの容量 |

- 予算の超過は CI の簡易ベンチで検知(回帰の監視)。CI は `minimal` を走らせる。
- 数値は最初の実装が動いた時点で計測して置く。先に決めた数字に
  実装を合わせるのではなく、達成できた値を回帰の基準線にする。

## 7. 障害モード

| 障害 | 挙動 |
|---|---|
| 2重起動 | ロックで検知し、後発は接続切替。データ破損の余地を作らない |
| アクターの panic | 診断イベント+再起動(可能なもの)。不能なら該当機能の退化を通知 |
| プラグインの起動遅延 | 段階的起動で他機能を先行。遅延プラグインは準備でき次第参加 |
| 前回の異常終了 | 起動シーケンス §1-8 で検出・片付け。報告は次のターンでコンパニオンが話す |
| ディスク満杯 | ストア書き込みエラー → 対話の停止+通知(データ保全優先) |
| 設定の不正 | 該当キーを defaults に戻して起動+警告(起動不能にしない) |
| バックアップ中のクラッシュ | online backup は整合コピーのみ残る。中途ファイルは起動時に掃除 |

## 8. 設定キー

数値は実装しながら決める(D-29)。

| キー | 説明 |
|---|---|
| `core.data_dir` | 全永続化の根(既定はプラットフォーム標準のデータディレクトリ) |
| `core.backup.auto` | 自動バックアップ(既定 `true`) |
| `core.backup.retention` | 保持世代 |
| `core.background_pool.workers` | 背景作業ワーカー数(補助LLM の呼び出しもここ) |
| `core.plugins.circuit_breaker.max_failures` | ブレーカー閾値 |
