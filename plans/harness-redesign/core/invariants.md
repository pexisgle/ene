# 不変条件と検証

> 実現する要件: **P-502**(model-visible = logged の検証)、P-510 の検証面。
> 参照: pi Part 9(invariants・race catalog・test tiers)を Ene 向けに再構成。

この文書は、core/ の4文書([storage-model.md](storage-model.md)、
[session-log.md](session-log.md)、[operations.md](operations.md)、
[durability.md](durability.md))が主張する性質を、**検証可能な形**で
一覧化する。設計の正しさはここにある。実装はこれらのテストを通すこと。

## 2. 競合カタログ

各競合には**ちょうど2つの耐久履歴**がある。両方を、手動駆動で、
両方の順序でテストする。

| 競合 | 2つの順序 |
|---|---|
| 同一レーンへの `prompt` vs `prompt` | 一方が受理、もう一方は `LaneBusy` |
| `abort` vs 応答のセットルメント | マーカー先 → 正規化 `aborted` / 応答先 → stop reason を保持 |
| `abort` vs ツール結果のコミット | 計画結果を合成 / 実際の結果がそのまま成立 |
| `abort` vs pre-step のフォローアップ | フォローアップは破棄 / コミットされて run が継続 |
| `cancelQueued` vs checkpoint 消費 | `cancelled` / `already_consumed` |
| `set_model` vs 生成ステップの開始 | 旧スナップショットを使用 / 新スナップショットを使用 |
| `abort` vs 構造変更のコミット | マーカー先 → エントリなしで `aborted` / 構造コミット先 → `completed` |
| `next_run` vs 受理 | 今回の run が捕獲 / 次回のために残留 |
| 手動コンパクションの予約 vs アイドルツリーの書き込み | 予約先 → 書き込みは待機 / 書き込み先 → 準備は新 leaf を使用 |
| 遅延書き込み vs abort | 書き込みはどちらでも abort を生き延びる |
| `close` vs 保留中の手動操作 | 操作は実行せず拒否。耐久状態はコミット済み接頭辞 |
| `close` vs セットルメント | セットルメントは放棄され `effect_pending` のまま / フラグ設定前にコミット済み |
| 音声割り込み vs TTS 再生完了 | 割り込み先 → `interrupted` で確定 / 再生先 → 通常完了 |
| `delegate.cancel` vs 子の完了コミット | cancel 先 → `cancelled` / 完了先 → cancel は `already_completed`([delegation.md §11](delegation.md#11-障害モード)) |
| 子の `question` vs 親の `delegate.answer` | 質問先 → 回答が届く / 取下げ先 → 回答は `not_found`(再試行安全) |
| 報告 wake の滞留 vs ユーザー発話 | ユーザー wake が常に先。報告は次ターン境界で結合して届く |
| 質問のタイムアウト仮定 vs 遅着した回答 | 仮定成立後 → 回答は棄棄されログに残る(子は仮定を維持)/ タイムアウト前 → 回答を採用 |

## 3. テスト階層

### 階層 A — 状態と再開

[operations.md](operations.md) のすべての状態について、
耐久化 → close → reopen → 次の動作の検証を行う。カバレッジは次を含む:

- 分岐走査・設定逆参照なしの復元。
- セットルメントなしのアシスタント意図(再試行上限の前後)。
- セットルメント後の各分類分岐。
- 自己完結する deferred ステップ(設定コピー・連続 poll・
  同一ハンドルの pending 応答の繰り返し・ready と terminal の応答・
  ハンドル不一致の正規化)。
- すべてのツール状態(planned・effect_pending の safe/unsafe・completed)。
- 全呼び出しが `terminate` を付け、追加要求なしに終わるバッチ。
- すべての溢れクラッシュ位置。
- すべてのコンパクション状態(移動後の生成なし)。
- すべての位置でのアボート。
- すべての終端トランザクションがレジスタの完全削除
  (クラッシュ漏れキーのプレフィックススキャン掃除を含む)・
  `lane.last_result` の正しさ・保持された `pending_next_run` を示すこと。
- すべての予約 id の、すべてのクラッシュ境界でのレジスタ/entry 排他性。
- すべての回復途中の接頭辞。

**各回復接頭辞ごとに**: close → reopen → resume → 中断なし回復との比較。
初期接頭辞から回復を2回呼ぶだけでは**不十分**。

破損アサーション: `running` の control で直接 `aborted` 応答を作り、
ロード拒否を要求する。プロバイダ適合テストは別途、
実装が与えられたシグナルに対してのみ `aborted` を出すことを検証。

### 階層 B — 書き込み適合性

公開ハーネスを**計測ストレージデコレータ**に対して走らせる:
`commit()` を包み、すべてのトランザクションの書き込みを順に記録するスパイ。
書き込みの順序と内容を、[operations.md §4](operations.md#4-原子遷移規則) の
遷移表と照合してアサートする。比較用の耐久ログは存在しない。
デコレータがオラクルである。

この階層が捕捉する重大な回帰クラス:

- 意図コミット**前**に効果が開始する。
- ある stop reason で応答が欠落する。
- usage が耐久化される**前**に分類が開始する。
- 結果 id がクリア開始**後**に予約される。
- 終端トランザクションがレジスタをリークする。

### 階層 C — 決定的インターリーブ

§2 の全競合を、両方の順序で、手動駆動で。

### 横断要件

- **バックエンド適合性**: 1スイート・全バックエンド・同一結果。
  シナリオごとの同一のクエリ結果・レジスタ状態・統計。
  書き込み順序のアサーションは計測デコレータを使い、耐久ログは使わない。
- **駆動の等価性**: 同一シナリオの自動駆動と手動駆動が、
  バイト同一の耐久状態を産む。
- **シグナルの所有**: 公開面はシグナルを受け取らない。
  シグナルを運ぶ要求は剥奪される。型とテストでアサート。
- **台帳完全性**(I-8)。
- **クエリ計画のガード**: 分岐走査の `EXPLAIN QUERY PLAN` が
  インデックス走査であることを確認(全 entries スキャンの禁止)。
- **トランザクション規律**: すべてのトランザクションが
  `BEGIN IMMEDIATE` で開くことをアサート。「読み → 他接続コミット →
  書き込み」が成功する回帰テスト(遅延 `BEGIN` では
  `database is locked` で失敗する)。
- **計測の秘匿性**: スパン属性にコンテンツ(プロンプト・補完・
  ツール引数/結果・ファイル内容・資格情報)が含まれないことを、
  属性スキーマの宣言性と CI 走査で検証
  ([observability.md §3](observability.md#3-プライバシー規則絶対))。
